# 项目状态与未保存保护完善计划

## 1. 背景

工作台同时承载歌词打轴 `.sug` 项目和字幕渲染 `.yurika` 项目。歌词打轴模块已经具备集中式 dirty 状态、保存生命周期、退出确认、临时保存和恢复能力；字幕渲染模块目前只有页面内部的 `_project_dirty` 布尔值，新建和打开项目时会确认未保存改动，但宿主关闭、更新退出、工作流状态展示和崩溃恢复尚未形成完整闭环。

本计划的目标是让用户在正常退出、切换项目、更新退出、保存失败和程序异常结束时都不会静默丢失项目修改，并让当前项目状态在页面和工作流步骤中始终可见。

## 2. 范围与约束

- 覆盖歌词打轴 `.sug` 和字幕渲染 `.yurika` 两类项目。
- 不直接修改 `krok_helper/lyrics_timing/` submodule 源码；宿主只使用其公开嵌入接口，必要时在宿主侧增加兼容适配。
- 用户可见字符串使用中文。
- 项目状态与应用级偏好分离：只有写入项目文件、影响项目重现结果的内容才标记 dirty。
- 导出视频是后台任务状态，不等同于项目 dirty，但退出时必须单独保护。
- 保存失败、另存为取消或异步保存未完成时，禁止继续退出。

## 3. 目标状态模型

每个项目模块至少向宿主报告以下状态：

- 是否存在当前项目或可保存内容；
- 当前项目路径、显示名称、是否未命名；
- 是否有未保存改动；
- 是否正在保存、最近一次保存是否失败；
- 是否正在执行不可直接中断的后台任务；
- 是否存在可恢复快照；
- 项目引用的素材是否缺失。

推荐把生命周期拆成三个互不混淆的维度：

1. 项目：空 / 未命名 / 已命名；
2. 持久化：已保存 / 未保存 / 正在保存 / 保存失败；
3. 任务：空闲 / 导出中 / 正在停止。

## 7. 验收标准

- 修改任一项目持久化字段后，页面和工作流步骤在一次事件循环内显示未保存。
- 正常关闭时，任何未保存项目都不会在无提示的情况下丢失。
- 保存失败、取消另存为或异步保存未完成时，工作台保持打开。
- 两个项目同时未保存时只出现一个汇总确认流程。
- 更新器强制退出后，下次启动可以恢复退出前的字幕和打轴修改。
- 自动保存不会把正式项目误判为已保存。
- 项目打开和保存的既有格式保持兼容。

1. 完成 P0 状态协议和 dirty 覆盖。

4. 实施 P1 原子保存、自动保存和恢复。
5. 最后实施 P2 备份、外部冲突和诊断增强。
