## B. 双模式数据流

### Standalone
- **入口**：`python -m krok_helper.subtitle_render`；项目命令栏或 `Ctrl+N/O/S/Shift+S`
- **加载**：三个独立选择按钮——字幕（`.sug` / `.lrc`）/ 背景视频 / 音频
- **存储**：项目 → `.yurika`；全局首选项 → `AppSettings.subtitle_render` dict
- **装饰**：独立窗口标题 + 项目命令栏；当前没有传统 `QMenuBar/QStatusBar`

### Embedded
- **构造**：`SubtitleRenderWindow.for_embedding(parent, settings_provider, workflow_context)`
- **上游数据**（自动获得，左侧素材区只读）：
  - 字幕：优先直接读取嵌入式 SUG 的 `ProjectStore.project`；打开已有文件时也可读取 `.sug`。`.lrc` 仅作为既有 Nicokara 逐字 LRC 的兼容入口，不再要求第 4 步先导出中间 LRC。
  - 背景视频：`context.aligned_video_path`（第 2 步对齐后的 1080p60 mp4），**默认作为背景层**
  - 音轨：与背景视频同源（mux）或独立流
  - 偏移：`context.alignment_offset_ms`
- **下游交付**：写 `context.subtitle_video_path`，发 `workflow_step_completed` 信号
- **宿主关系**：与 standalone 共用项目命令栏和编辑界面，由 `for_embedding()` 注入设置桥与 WorkflowContext

### 设置桥
- 骨架已实现 `KrokHelperSubtitleRenderSettingsBridge`（`krok_helper/subtitle_render/settings_bridge.py`），仿照 SUG 的 `KrokHelperSettingsBridge`（`gui_qt.py:182-244`）
- 暴露字段示例：`default_font_family` / `default_resolution` / `default_fps` / `prefer_hwenc` / `output_dir` / `recent_style_presets`——存进 `AppSettings.subtitle_render` dict 的对应 key

### 各区组件（qfluentwidgets 渐进引入，歌词列表已完全 fluent 化）

- **顶部项目命令栏**：新建 / 打开 / 保存 / 另存为 / 预览窗口；standalone 与 embedded 都显示
- **素材与导出控制**：字幕 / 背景视频 / 音频选择与加载状态、输出参数和渲染按钮
- **左·歌词列表**：qfluentwidgets `TableWidget`，四列——`轨` / `角色`（双击弹出 FluentComboBox 下拉选配色方案）/ `特效`（双击编辑逐行入退场动画，右键批量应用）/ `内容`（歌词文本，只读不可编辑）。表头可见，行高紧凑布局。点击整行跳转预览到该句起始时间戳；playhead 高亮当前行（待接入 painter 时间同步）
- **中·预览区**：`QGraphicsView` + 自定义场景——当前产品路径用 `QMediaPlayer.setVideoSink` 取视频帧，字幕层由 QPainter 离屏叠加；纯色 / 静态图 / 图片序列背景待 B6 接通。预览与导出共用同一 `paint_frame`
- **中·播放控件**：播放 / 暂停 / 时间码 / 跳转滑块；由统一播放控制器同步视频、音频和字幕时钟
- **右·属性面板**：`QTabWidget` 五标签 —— 基本（屏幕预设 / 像素纵横比 / 宽高 / 视图）/ 字幕（字体 / 字号 / 颜色 / 描边 / 阴影 / 角色方案管理）/ 特效（动画 / 渐变 / 发光）/ 装饰（时段图片 P2）/ 标题（标题字幕编辑）；每个标签内用 `SettingCardGroup` 折叠分组
- **底·字幕轨道**：`QGraphicsScene` 自绘——多行（T1/T2/T3）色块，每行展示一段歌词的演唱区间，块内细分到字符级；按演唱者上色；点击块可定位到对应行 / 字
- ~~底·波形~~：**已弃用**，不做波形图功能

## E. 渲染引擎技术选型

**已选定：QPainter 离屏 + ffmpeg rawvideo pipe**（不要改方案，已与用户达成一致）

- 当前流程：枚举每帧 t → `QPainter` 画到 `QImage(Format_RGBA8888)` → bytes → ffmpeg stdin (`-f rawvideo -pix_fmt rgba`) → 与背景视频合成并编码；B6 完成后再扩展为通用背景输入 + 独立音频输入
- **关键优势**：
  1. 卡拉ok填充逐像素精确，渐变/发光/动画完全自由
  2. **预览与渲染共用 QPainter 绘制函数**，所见即所得
  3. 直接复用 `krok_helper/ffmpeg.py` 的 `run_command` / `find_tool` / `probe_media`
  4. 硬编探测沿用 `audio_alignment.py::export_aligned_video_v2`（参考其分支判断写法）
- **缓解 CPU 占用**：多线程绘帧（producer N×QPainter → 队列 → 单 consumer 喂 ffmpeg），目标 1080p60 实时倍率 ≥ 0.5×

**预览策略**：同引擎降分辨率（`QImage(960, 540)`），定位用 `QMediaPlayer.setPosition()` 取静态背景帧，叠加 QPainter 字幕。保证"预览=输出"。

**否决方案**（避免重新讨论）：
- ❌ 生成 `.ass` + libass burn-in：渐变 / 发光 / 复杂动画表达受限；预览路径割裂。可作为 P2 "极速导出"按钮，但不是主路径。

## I. 行背景带（三段式背景条）— 设计定稿（2026-10-23）

### I.1 需求定位

每条歌词行背后铺一条**图片带**：宽度跟随该行文本宽度，高度按行高的倍数可调（含是否把注音算进去）；图源全局一张（用户上传或内置预设），静态不生长，与该行共用同一个显示窗口和入场/退场动画。典型素材是"左右有装饰、中间可无限延长"的横幅图（五线谱、竹林、水泡）。

**不是**围住字形的卡片。带子只参与绘制，**不参与排版**：不改变行网格、行宽、页偏移和防重叠包络（`LineVisualBand` 仍按墨迹测）。

### I.2 数据模型（`Style` 字段，全局一份）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `line_band_enabled` | bool | False | 总开关 |
| `line_band_image` | str | `""` | `preset:<id>` 或绝对路径 |
| `line_band_dynamic_notes_enabled` | bool | True | 五线谱中段动态音符开关 |
| `line_band_static_notes_enabled` | bool | True | 五线谱两端静态音符开关 |
| `line_band_fill_mode` | str | `"three_slice"` | `stretch` / `repeat` / `cover` / `three_slice` |
| `line_band_cap_left_px` | int | 0 | 左端点宽（**源图像素**，左右独立） |
| `line_band_cap_right_px` | int | 0 | 右端点宽（源图像素） |
| `line_band_mid_mode` | str | `"repeat"` | 三段式下中段：`repeat` / `stretch` |
| `line_band_pad_top_px` | int | 20 | 上边距：可见文字（墨迹 + 描边；含注音时取注音顶）→ 带子上缘 |
| `line_band_pad_bottom_px` | int | 20 | 下边距：可见主文字（墨迹 + 描边）底 → 带子下缘 |
| `line_band_pad_left_px` | int | 40 | 左边距：可见主文字（墨迹 + 描边）左缘 → 带子左缘 |
| `line_band_pad_right_px` | int | 40 | 右边距：可见主文字（墨迹 + 描边）右缘 → 带子右缘 |
| `line_band_include_ruby` | bool | False | 上边距的基准是否取注音顶 |
| `line_band_offset_y_px` | int | 0 | 垂直微调 |
| `line_band_opacity_pct` | int | 100 | 整体透明度 |
| `line_band_tint` | str | `""` | 用户颜色（仅可调色预设生效），空=用预设默认色 |
| `line_band_tint_strength_pct` | int | 100 | 上色强度，0=原样中性灰 |

**四边锚点口径（2026-10-29 修正）**：默认按**可见文字盒**——主字形墨迹（`_line_main_text_ink_rect` / native `textInkBounds`）并外扩当前生效的描边/二重描边一半，左右/上下都从同一可见盒量起。整行墨迹过扁（全是「ー」/标点）时回退字体 `ascent/descent` 盒，避免带子被压成一条细线；有行内音量柱时仍取旧内容盒，保证带子包住柱体。CPU 与 GPU 共用同一口径。

**没有"行高倍数"这个字段**（2026-10-23 用户口径：行几何不能写死）。带子的宽高完全由可见文字盒（墨迹 + 描边，扁平行回退字体盒）加四边内距决定，上下左右各自独立可调，不做对称联动。

这组字段全部进 `main_window._PAINT_ONLY_STYLE_FIELDS`（纯绘制，不影响排版 → 拖滑块不触发全量重排）。

### I.3 几何

四边取自**同一套文字包围盒**，各自加各自的内距——不做"居中 + 高度倍数"的隐含约束：

```
text_box = text_layout.line_rect            # x0 / 顶 / 总宽 / ascent+descent
top_ref  = text_box.top()                   # 主文字 ascent 顶
if line_band_include_ruby and 该行有注音:
    top_ref = min(top_ref, 注音顶)          # 从 layout.ruby_layouts 的 baseline_y 推，不重算

band_left   = text_box.left()   - pad_left
band_right  = text_box.right()  + pad_right
band_top    = top_ref           - pad_top
band_bottom = text_box.bottom() + pad_bottom
band_w      = band_right - band_left
band_h      = band_bottom - band_top
整条再按 offset_y_px 平移
```

要点：

- **上下边距互不影响**：加大上边距不会把文字往下压，带子只向上长。
- `include_ruby` 只改基准点（主文字顶 ↔ 注音顶），下缘始终跟主文字底走，所以开关注音时带子底部不跳。
- **带子宽度必须容得下两端**：`band_w < cap_left*s + cap_right*s` 时三段式会压缩端点（谱号/装饰会变小）。预设因此带"建议最小边距"，UI 在用户把左右边距调到挤压端点时给提示，但不阻止。

### I.4 四种填充

| 模式 | 缩放 | 平铺 | 适用 |
|---|---|---|---|
| `stretch` | `sx=w/iw, sy=h/ih`（非等比） | CLAMP | 渐变、斜纹 |
| `repeat` | `s=h/ih`（等比、贴合带高） | 横向 WRAP | 五线谱（线宽不变） |
| `cover` | `s=max(w/iw, h/ih)`（等比覆盖） | CLAMP，居中裁溢出 | 竹林（有细节，不能拉伸） |
| `three_slice` | 纵向统一 `s=h/ih` | 左右端点不缩放内容，中段按 `mid_mode` | 带装饰的横幅 |

三者都只产生一组 `(sx, sy, tx, ty, extend)`，几何全在 Python 算，C++ 只套矩阵。

### I.5 三段式算法

```
s        = band_h / img_h                 # 纵向统一缩放，装饰不变形
左目标宽 = cap_left_px  * s
右目标宽 = cap_right_px * s
中段宽   = band_w - 左 - 右
```

- **中段重复**必须先把中段那一条从源图裁出来，作为独立平铺单元，相位从左端点右缘起算。**不能**用"整图平铺再裁中间"模拟——相位错位会露缝。
- 退化：`带宽 < 左+右` 时按 `s' = 带宽/(左+右)` 重算，中段宽取 0；建字段时就钳制 `左+右 ≤ 图宽-1`；换图后端点超界自动钳到新图范围。

### I.6 渲染层级：两遍绘制

行距通常是 1.0–1.5 × 行高，带子按倍数居中后，**倍数 ≥1.3 时下一行的带子会压住上一行的字**。因此不能塞进 `_paint_line_static`，要在 `_paint_track_to_painter` 的行循环**之前**插一遍"带子预扫"：

1. 复用 `line_animation_state()`（纯函数）取每行的 `dx/dy/opacity`，套到带子上；
2. 预扫把 `LineLayout` 透传给后续绘制，避免 `_layout_line` 算两遍；
3. 画完所有带子，再走原循环画字。

这样既保住"跟同一句同动画"，又保证带子永远在字下面。

### I.7 预设与资产

**2026-10-23 第二轮（用户实测后）改版口径**：

- **宽幅不循环**：中段一律 **4096px**（`diagonal` 4080，保证条纹周期 40 整除），16:9 画布上的正常歌词行不会再铺第二块。素材总量随之变大（五张合计约 1MB），可接受。
- **谱线独立成层（2026-10-23 第二次返工）**：五线谱的 5 条谱线**和高音谱号一起**放进 `staff_scroll_lines.png`——谱号=白色字形 + 近黑描边（PIL `stroke_width=9`），谱线=纯白 3px。运行时对整层做**逐通道 multiply**（不是压成单色剪影）：白色被乘成用户颜色，近黑描边保持近黑，所以「改谱线颜色时谱号一起变色，且谱号仍有描边」。图层顺序固定为 **谱线层（含谱号）→ 音符/终止线**，谱线永远压在谱号下面，不会横穿谱号。素材本体不再画谱线和谱号，避免重复。
- **端点单位修正（2026-10-23）**：`LineBandStyle.capLeft/capRight` 一律是**源图像素**，绘制端自己乘 `带高/图高`；投影期再乘 dpr 会二次缩放（dpr=2 时端点宽变 4 倍，画面出现重复/挤压）。
- **图片描边效果**：`line_band_edge_kind` = `none` / `shadow` / `glow`，颜色、半径、投影 X/Y 偏移、强度都可调。实现是「把素材 alpha 压成单色剪影 → 按半径降采样模糊 → 发光绕圆周 16 次轻叠把轮廓扩出去 / 投影按偏移画一次」，CPU 与 GPU 同口径。
- **用户上传图**：文件对话框收 PNG / GIF / APNG / WebP / JPG / BMP / TIF；GIF 取第一帧（逐帧动画尚未实现），透明通道保留。

- **格式**：PNG（带 alpha）。**不能用 SVG**——GPU 走 WIC 解码位图。
- **位置**：`krok_helper/assets/subtitle_render/band_presets/`（沿用已有 `SUBTITLE_RENDER_ASSET_DIR`）。
- **持久化**：预设存 `preset:<id>`，运行期解析成绝对路径再喂渲染与 IR；**不存绝对路径**（打包后资源在 `_MEIPASS`/`_internal` 下，更新即失效）。用户上传存绝对路径，并接入 `find_missing_project_resources` 报「行背景图」。
- **元数据**：`krok_helper/subtitle_render/domain/band_presets.py` 一个 `BandPreset` 表（id / 名称 / 文件名 / 左右端点 / 建议四边边距），UI、CPU、IR 共用。
- **预设自设**：高统一 240px；左右端点内缘与中段严丝合缝；中段必须横向首尾无缝循环。
- **视觉基线（2026-10-23 定，五线谱除外）**：预设走"材质化"路线，不做纯色平涂——纵向渐变底 + 顶部内高光 + 底部内阴影，端点局部发光；星火/气泡/缎带这类装饰必须有 specular 高光与柔光晕。中段装饰允许柔光，但必须做成"跨接缝环绕绘制"（`draw_tile` 3 倍画布裁中段），否则光晕在接缝处被硬切。
- **各预设视觉定稿（v10，2026-10-23 用户确认"几乎满意"）**：
  - `staff_scroll` 五线谱：**全透明**无底板；纯黑五线（3px）+ 真高音谱号 + 四色音符（朱红 `#D14A4F` / 靛蓝 `#3A6EA5` / 叶绿 `#4E8A5E` / 赭橙 `#D38324`）+ 一层柔和投影（模糊 3.2、62% 不透明、偏移 2,3）。细则见下条专项。
  - `stars` 星火：**单色白**（不做多色光晕），少量小四角星 + 极淡深色底 + 一条顶光；比早期版本更素净。
  - `diagonal` 斜纹缎带：中性灰缎面（顶近白→底中灰）+ 45° 条纹（周期 40，必须整除中段 320）+ 圆角端点 + 端点内折边收口；运行时 multiply 用户色。
  - `bubbles` 水泡：**海水**（《凪のあすから》那种水下感）——深青纵向渐变（上亮下暗）、9 条焦散亮线（跨接缝连续）、端点内水面光柱、大小混合气泡、上下边缘羽化。早期"黑色半透明方框"方案已废，不要再回到方框 + 少量气泡的画法。

- **五线谱专项（2026-10-23 用户定稿）**：**全透明**，没有底板——只保留黑色五线谱线、真高音谱号、彩色音符和一层柔和投影。谱号用字体 U+1D11E（Segoe UI Symbol）取字形，**不要手画**；音符**必须复用项目里的轮廓** `engine/render/effects/particles.py::_note_commands()`（±500 em 八分音符，与成片里"音符飘出/指示灯"同形），不要另行设计。音符是唯一的有色元素；两端各放两个静态音符，中段可选缓慢漂浮的小音符（2026-10-30 起由两个独立开关控制）。该预设配**深色字 + 浅色描边**，建议边距 26 / 26 / 110 / 120（左右要能容下谱号与终止线）。端点因此加宽到 190/160（中段仍为 320，保证循环宽度不变）。
  - **符干接缝（2026-10-23 修正）**：项目轮廓的符干左缘只画到 y=-330，而符顶在 y=-380，中间是一个楔形缺口，直接放大填充会看到"符尾没接到柱子上"。渲染时必须**按符干宽度补一段顶端收圆的胶囊**（em 坐标 x∈[30,80]、y∈[-380,-292]、圆角 25）再叠符尾，接缝才顺。
  - **音符显隐开关（2026-10-27 / 2026-10-30）**：`line_band_dynamic_notes_enabled` 控制中段漂浮音符，`line_band_static_notes_enabled` 控制左右两端静态音符，均默认开。素材侧四种组合：主 `staff_scroll.webp`（两端 + 中段）、`staff_scroll_static.png`（仅两端）、`staff_scroll_dynamic_only.webp`（仅中段）、`staff_scroll_no_notes.png`（全透明底板）。两个都关时只剩独立谱线层与谱号层；谱线/谱号颜色等设置照常生效。属性卡「图源」组只在五线谱预设下显示这两行。

- **选中预设**：一次写入 image + 左右端点 + `three_slice` + 建议四边边距。**上传自定义图**：端点清零、模式不变（三段式 + 0 端点自然退化为整条重复）。

| id | 名称 | 左/右端点 | 建议边距 上/下/左/右（px，1080p 参考） | 可调色 |
|---|---|---|---|---|
| `staff_scroll` | 五线谱 · 卷轴（透明五线） | 190 / 160 | 26 / 26 / 110 / 120 | 否 |
| `stars` | 星火点阵（素净单色） | 120 / 120 | 14 / 14 / 54 / 54 | 否 |
| `diagonal` | 斜纹缎带 | 96 / 96 | 10 / 10 / 42 / 42 | **是**（默认 `#3EC6E0`） |
| `bubbles` | 水泡（海水） | 160 / 160 | 18 / 18 / 78 / 78 | 否 |
| `plain_round` | 纯色圆角条 | 64 / 64 | 50 / 50 / 50 / 50 | **是**（默认 `#2B3A55`） |

选中预设时把这四组边距一并写入，用户之后可以任意改。左右边距的默认值都**大于等于该预设端点的缩放后宽度**，保证一选出来文字不会被谱号/装饰压住；用户调小到以下会挤压端点，UI 只提示不阻止。

**可调色实现**：可调色预设的素材按**中性灰材质**生产（高光/阴影/描边都在亮度里），运行时向用户颜色混合上色，alpha 不变：`C_out = (1-k)·C + k·tint`（k = 强度%）。强度 100% 时等于把素材压成单色剪影，所以**带内部明暗细节的素材不要默认开满强度**。CPU 侧缓存 `(路径, mtime, 颜色, 强度)` 的 tinted QImage；GPU 侧在 configure 期按同一公式在 WIC 解码的预乘像素上烘一次（`P_out = (1-k)·P + k·tint·alpha`）并缓存，渲染期只做 `DrawBitmap`，不逐帧算。

**三段式的循环约束（2026-10-23 实测踩坑）**：中段里任何**有周期**的图案（斜纹、网格、重复花纹），其周期必须**整除中段宽度**，否则每铺一块相位就跳一次，成片是一条条错位的接缝。本次 `diagonal` 中段 320px，条纹周期必须取 40（320/40=8），取 44 就会跳。自检方法：比较中段首列与"首列+1 列"的差，和末列与首列的差——后者不应明显大于前者。

**中段铺不满整块时的口径（2026-10-23 实测踩坑）**：`repeat` 允许最后一块被裁（CSS [border-image-repeat: repeat](https://developer.mozilla.org/en-US/docs/Web/CSS/border-image-repeat) 原文 "Tiles may be clipped"），裁切点正好落在右端点边界上，**方向性纹理**（斜纹）会在这里相位跳；实测沿中线量峰值，中段条纹周期 23.3px，一进右端点就变成 17~19px。标准解法是 `round` 语义（把中段整体微缩放，让整数块正好铺满），但窄带时缩放偏差可达 15%，条纹角度会随行长变化。产品口径：

- **方向性纹理**（斜纹）：用 `repeat` + 端点内做**折边**收口；折边必须画在端点里，压到中段循环单元上会导致每铺一块多一道线。
- **非方向性纹理**（横线、点阵、散点）：直接 `repeat`，半块裁切看不出来。

### I.8 UI

「特效」页第一组「行背景带」：开关 / 预设下拉 / **图片路径独占一行**（与预设同排会被挤没） / 填充方式四选一 / 三段式下中段模式 / **卡片内实时预览条** / 左右端点 / 四边距 / 含注音 / 垂直偏移 / 透明度 / 上色与强度 / **谱线颜色** / **图片描边（投影·发光）颜色·半径·偏移·强度**。

**控件口径（2026-10-23 用户要求「和指示灯-相对字号一样」）**：所有数值都用 `CanvasSliderSpinBox` + `_add_canvas_spin`（可拖滑条 + 数值输入，画布比例自适应）。
**右端点滑条取反值**：控件显示 `-cap_right`（范围 -4096..0），向右拖 = 切割边界向右移；左右端点由 `_line_band_cap_left_value` / `_line_band_cap_right_value` 夹住，保证 `cap_left + cap_right ≤ 素材宽度`，永不相交。
**全局 scope**：行背景带字段不属于配色方案，所有控件与取色必须带 `_force_global=True`（`_global_color_button`），否则在选中角色方案时改动会被写进方案、画面不变。
**预览条**：棋盘格透明底（纯黑/纯白都会让部分素材看不见）；高度按「字号 × 输出缩放 + 上下留白」推出真实带高，再整体等比缩到卡片宽度——所以**重复度与成片一致**；重复单元就是切掉左右端点后的中段，黄色虚线标出端点边界。

禁用条件：竖排（带子的竖排等效物是竖列，第一期不做）。双行布局按一排两 lane 的并集画一条带子。

**平铺无缝（2026-10-23 用户实测「每个预设拼接痕迹都很明显」）**：逐块 `drawImage`/`DrawBitmap` 时每块边缘各自 clamp 采样，块与块之间必留一条半像素竖线；位图画刷 `WRAP` 在非整数缩放下回绕处也会断一拍。最终口径是**中段预拼成一条连续纹理再一次取样**：CPU 侧 `_mid_strip`（按瓦片整数像素拼条并按块数缓存），GPU 侧 configure 期把中段瓦片拼成 8192px 宽的位图（`CachedBandImage::midBitmap`），绘制时一次 `DrawBitmap(dest, srcRect)`。回归测试 `test_preset_middle_tiles_wrap_without_a_visible_seam` 守住素材首尾列连续。

**出入场（2026-10-23 用户口径）**：带子严格限制在正文显示窗 `[display_start, display_end]` 内——入场预演/退场粒子尾奏只有粒子、带子不画；对逐字/几何特效（雪、花瓣、粒子等，没有行级透明度曲线）按与正文**同一过渡窗口**（`entry_duration_ms`/`exit_duration_ms`，缺省 600ms）做 smoothstep 淡入淡出，不加额外粒子。`fade/slide_in/rise` 仍走原行动画曲线，不重复叠透明度。
