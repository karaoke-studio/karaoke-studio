## 1. 目标与边界

目标不是逐字段复制 NicoKaraMaker3 的全部编辑器和输出格式，而是：

1. 导入 N3 工程后，卡拉 OK 字幕的视觉、布局、逐字时间、角色和逐行特效尽量保持一致；
2. 对产品明确不支持的能力采用确定的降级规则，不把它们长期伪装成“待实现”；
3. 无法无损映射时给出中文提示，不能静默应用错误设置；
4. 所有新增映射按 TDD 落地，并用真实 N3 工程做回归。

当前实现入口：

- `krok_helper/subtitle_render/n3proj_import.py`
- `krok_helper/subtitle_render/models.py`
- `krok_helper/subtitle_render/project_store.py`
- `krok_helper/subtitle_render/frontend/main_window.py`
- `krok_helper/subtitle_render/engine/painter.py`

## 2. 当前兼容矩阵

### 2.1 素材与画面

| N3 能力 | 当前状态 | 当前行为 | 目标/决策 |
|---|---|---|---|
| `SourceKind=0 Movie` | ✅ | 解析绝对/相对视频路径，进入现有视频预览与 MP4 导出 | 保持 |
| `SourceKind=1 Image` | ✅ | `ImagePath/ImageRelativePath` → 静态图片预览与循环导出 | 保持 |
| `SourceKind=2 SequenceImage` | ✅ | 图片编号模式、源 FPS 与起始编号进入预览、项目和导出 | 遇更多真实样例继续补命名兼容 |
| `SourceKind=3 Background` | ✅ | `BackgroundColor` → 纯色预览与 lavfi 导出 | 保持 |
| `SoundPath` 独立音频 | ✅/有限 | 图片、图片序列和纯色背景可加载、预览、持久化并导出；视频背景会提示并忽略 | 视频只使用内嵌音轨，避免双时钟 |
| 宽高 | ✅ | `BackgroundWidth/Height` →输出屏幕 | 保持 |
| FPS 60/120 | ✅ | 原样导入 | 唯一支持档位 |
| 其他 FPS | ✅ 降级 | 回退 60 并提示 | 明确不支持 30fps 原样输出 |

`BackgroundSource` 已成为正式产品模型；`RenderJob.background_video_path` 仅保留为旧调用
兼容入口，新路径统一使用 `background_source` 与可选 `audio_path`。

- 发光浓度主字/ruby 均为中档；
- 主字与 ruby 二重描边均关闭；
- ruby 字号 45、描边 2、二重描边 0；
- 走字后为蓝白配色；
- 默认布局字间距 7px。

### 2.3 布局与分页

| N3 能力 | 状态 | 备注 |
|---|---|---|
| 上/中/下锚定、余白、行距 | ✅ | 多布局可保存 |
| 每行水平对齐列表 | ✅ | 支持任意行数 |
| SmartHorizon | ✅ | None/Single/Multi 语义已对齐 |
| 多布局定义 | ✅ | 默认布局在 `Style`，额外布局在 `Style.layouts` |
| 每行 `LayoutIndex` | ✅ | 按页应用、自动选择器和 `.yurika` 持久化已实现 |
| PageBreak/ParagraphBreak | ✅ | N3 显式恢复，LRC 路径可重建 |
| SizeAndRatio | ✅/有限 | 布局几何随参考高度缩放 |
| 字符排版参数 | ⚠️ | 五项的模型、导入、Painter 和 UI 已完成；产品按全局/角色配色方案应用，不逐 `LyricsLayout` 保存。额外布局差异会提示并按默认布局值导入 |

已支持但不进入每个 `LyricsLayout` 的五项：

- `LyricsInterval` → `letter_spacing_px`
- `AllowBiting` → `allow_biting`
- `RubyInterval` → `ruby_interval_px`
- `RubyAlignment` → `ruby_alignment`
- `LyricsAndRubyInterval` → `ruby_gap_px`

这些是排版参数，不是字体视觉参数。字体族、字号、字重、颜色、描边和发光继续属于角色/样式。

建议生效顺序：

1. `Style` 提供默认布局值和旧工程兼容；
2. 角色/歌手方案解析字体和视觉样式；
3. 当前行引用的 `LyricsLayout` 最后覆盖上述五个排版参数。

这样同一角色在“下寄せ2行”使用 7px、在“下寄せ3行”使用 0px 时能保持 N3 语义。

### 2.5 标题

| N3 能力 | 状态 | 备注 |
|---|---|---|
| 标题文字、字体、配色、布局、显示时段 | ✅ | 映射为 `TitleOverlay` |
| 多个标题槽位同时有内容 | ⚠️ | 当前只导入第一个非空标题 |

TACTIC 有 `タイトル1/2/3` 三个槽位，但只有 `タイトル1` 有两行内容，后两个为空，当前导入无损。多标题列表化不阻塞当前主线；出现真实非空多标题样例后再升级为 `title_overlays: list[TitleOverlay]`。

### 2.6 输出

| N3 输出 | 决策 |
|---|---|
| MP4 | 支持；导入目标路径 |
| 未压缩 AVI | 不支持、不计划实现 |
| ARGB/透明 PNG 序列 | 不支持、不计划实现 |
| 完整 N3 MP4 编码预设 | 不做逐字段复刻；使用本模块 encoder/crf/preset 设置 |

## 3. 后续实施包

### N3-P1：字符排版参数（已收口）

五项参数的模型、序列化、N3 默认布局导入、Painter、属性面板和缓存签名已经接通，
TACTIC 默认布局 7px 也已有回归覆盖。当前产品架构将字符排版放在全局/角色配色
方案域；`LyricsLayout` 只保存位置与行结构。N3 额外布局的五项若与默认布局不同，
导入器继续给出有损提示并采用默认布局值。逐布局保存不再是当前主线，也不阻塞
N3-P2。

### N3-P2：背景源与独立音频（已完成）

目标模型：

```text
BackgroundSource
  kind: video | image | image_sequence | solid
  path: Path | None
  color: #RRGGBB
  source_fps: int | None
  sequence_start_number: int
  video_offset_ms: int
audio_path: Path | None
```

预览：

- video：现有 QMediaPlayer/QVideoSink；
- image：缓存单张 QImage；
- image_sequence：按 `floor(t_ms * source_fps / 1000)` 取帧并做小型 LRU；
- solid：画布直接填色；
- 音频由统一播放控制器独立播放。

导出：

- video：现有视频输入；
- image：ffmpeg loop 静态图至项目时长；
- image_sequence：按确认后的 N3 文件语义构造序列/concat 输入；
- solid：ffmpeg `color` lavfi；
- 非视频背景的独立 `SoundPath` 作为单独音频输入并映射到 MP4；视频背景忽略该字段并使用内嵌音轨。

已用 ffprobe 验收纯色+独立音频、静态图+独立音频、图片序列+独立音频、视频内嵌音频
四类 5 秒 MP4；四者均为 5.000 秒且同时包含 video/audio 流。

### N3-P3：范围提示清理

- 删除假名独立字体“待支持”警告；沿用日文字体，可记 debug 日志；
- 非 MP4 输出改成“将输出为 MP4”的普通提示；
- 保留非 60/120fps 回退提示；
- 保留素材缺失、未知笔刷、未知动作和真实多标题损失提示；
- 提示内容必须区分“产品明确不做”和“导入数据异常”。

- 新 `SubtitleActionId` 映射；

## 4. 明确不做与不阻塞项

- 30fps 原样输出；
- 假名独立字体族；
- AVI；
- ARGB/透明 PNG 帧序列；
- 逐字段复刻 N3 MP4 编码预设；
- 空标题槽位列表化；
- 为未知 N3 动作猜测最相近的本模块动画。

## 5. 验证与交付门槛

每个实施包必须：

1. 先添加失败测试，再实现；
2. 跑对应 N3 导入、模型、Painter、项目保存和 UI 测试；
3. 对真实样例导出至少走字前/中/后三帧，和 NicoKaraMaker3 截图对照；
4. 不改变未涉及字段，尤其不能强制开启二重描边；
5. 更新本文兼容矩阵和总需求文档状态；
6. 合并前跑 Windows PyInstaller 包内 N3 打开与 MP4 导出冒烟。

2026-07-13 完整测试 `901 passed, 50 skipped`，未复现此前的 pooled-thread
teardown access violation。若以后再次出现，优先检查预览 worker、QMediaPlayer 和
QApplication 的销毁顺序。

## 6. 当前推荐顺序

1. N3-P3 提示策略；
2. CLI/CI/打包收尾；
3. 遇真实样例再启动 N3-P4。
