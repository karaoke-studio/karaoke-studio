# 标题逐字符角色分配设计

> 日期：2026-07-12
> 状态：设计已确认，待实施
> 关联：`docs/逐字符角色分配UI设计.md`、`docs/N3项目导入兼容性与实施计划.md`

## 1. 背景与目标

歌词已经支持把角色方案分配到单个字符，但标题仍只能使用统一的内置“标题”
方案。N3 项目实际上允许标题的每个字符持有独立 `FontIndex`。样例
`D:\カラオケ\songs\異世界ガールズ♡トーク\1.n3proj` 的第一行同时使用：

- `【全員】2`：曲名；
- `情報小`：` / ` 分隔符；
- `【ターニャ】2`、`【アルベド】2`、`【アクア】2`、`【エミリア】2`：四段角色信息。

当前 `_title_first_font_index()` 只读取标题第一个字符的方案，把其余逐字分配
全部压平。本设计需要同时解决 N3 数据保真和 KS 内部可编辑性。

目标：

1. 无损导入 N3 第一个非空标题槽位的逐字符 `FontIndex`；
2. 在左侧歌词列表中把标题作为特殊文本源显示；
3. 复用现有逐字符角色对话框编辑标题；
4. 标题 Tab 修改文字时即时刷新左侧列表，并可靠迁移已有角色标签；
5. 支持预览、持久化和撤销/重做。

## 2. 已确认的产品决策

- UI 采用“标题作为特殊字幕源”，不把标题固定混入主字幕行，也不在标题 Tab
  另做一套逐字编辑器。
- 标题永远排在来源列表最后：`主字幕 → 各副字幕 → 标题`。
- 标题态只显示“行 / 角色 / 内容”，不显示轨道和特效。
- 标题整体共用一个布局方案，继续由标题 Tab 的 `layout_index` 控制；不做逐行
  独立布局。
- 未指定角色的标题字符继承内置“标题”方案。
- 首次逐字编辑含 `{title}` / `{artist}` 的模板标题时，把模板展开为当前实际文字并
  固定，再建立逐字符标签。
- 标题文字变化时，按文本差异迁移标签：相同字符保留，插入字符回到标题默认，
  删除字符连同标签删除，拆行/合行尽量保留未变化字符。
- 技术路线采用轻量标题行适配器，不把标题构造成虚拟时间轨道，也不重构整个
  歌词面板为新的通用数据系统。

## 3. 数据模型与持久化

### 3.1 `TitleOverlay` 字段

新增：

```python
char_role_labels: list[list[str | None]]
```

- 外层与固定后的 `text_template.split("\n")` 对齐；
- 每个内层列表与该行字符数严格相等；
- `None` 表示继承 `custom_style_schemes["标题"]`；
- 具名标签表示该字符应用对应角色方案；
- 换行符本身不占标签位置。

字段随 `TitleOverlay` 进入现有 Style/.yurika 序列化。旧项目缺失字段时按当前标题
文字生成全 `None` 矩阵，视觉结果保持不变。

### 3.2 当前项目角色注册表

新增项目级 `active_role_names: list[str]`，明确区分“当前项目可分配角色”和“预设
模板/未引用的 N3 方案”。注册表按首次出现顺序去重，来源为：

1. 主字幕实际角色；
2. 各副字幕实际角色；
3. 标题实际角色；
4. 用户在当前项目中新建但尚未使用的角色。

内置“标题”不进入注册表；它在标题编辑器中以“标题默认”表示。历史预设库、
以及 N3 中未被任何歌词或标题引用的方案不进入注册表。

旧项目没有注册表时，从所有歌词轨和标题标签推导。新增、重命名、删除角色时
同步更新注册表并持久化，避免重开项目后未使用的新角色消失。

## 4. 标题行适配器

新增只面向前端的 `TitleRowsAdapter`：

```text
TitleOverlay
  └─ TitleRowsAdapter
       ├─ 行 1 → TimingLine-like 字符视图
       ├─ 行 2 → TimingLine-like 字符视图
       └─ 写回 → TitleOverlay.char_role_labels
```

适配器只提供歌词面板已使用的字符文本与 `role_label` 接口。它：

- 不产生开始/结束时间；
- 不进入主字幕或副字幕轨道；
- 不参与预览跳转、lane 分组、逐行特效或 SUG；
- 不持有独立真值，写回始终生成新的 `TitleOverlay`。

这样可以复用现有混合角色检测、色点、整行覆盖确认和 `_CharRoleDialog`，同时
避免时间轨道逻辑被大量标题特判污染。

## 5. 左侧界面

### 5.1 来源顺序与生命周期

标题开关打开时，来源列表为：

```text
主字幕
副字幕 1
副字幕 2
标题
```

- “标题”恒为最后一项；新副字幕插入标题之前；
- 关闭标题开关时移除“标题”；若当前选中标题，自动切回主字幕；
- 关闭只影响显示与渲染，不删除标题文字、布局或角色标签；
- 来源选择使用稳定的来源类型标识，而不是依赖易变的组合框整数下标；
- 选中标题时，“＋”仍可添加副字幕，“－”禁用。

即使标题文字为空，只要开关打开，标题来源仍可选择，便于用户转到标题 Tab
输入内容。

### 5.2 标题表格模式

标题模式的可见列为：

| 行 | 角色 | 内容 |
|---|---|---|
| 1 | 混合 | 異世界ガールズ♡トーク / ターニャ… |
| 2 | 标题默认 | TVアニメ『異世界かるてっと』のEDテーマ |

- 第一列显示从 1 开始的标题行号；
- 内容列只读，标题文字仍在标题 Tab 修改；
- 角色列支持整行覆盖；混合行覆盖前沿用现有确认弹窗；
- 双击内容或右键“逐字符分配角色…”打开复用对话框；
- 不显示、不响应逐行特效、时间跳转和行布局菜单。

### 5.3 逐字符对话框复用

对话框增加基础方案上下文：

- 歌词模式：无标签按钮仍为“全局默认”；
- 标题模式：无标签按钮显示“标题默认”，色点来自内置“标题”方案；
- 标题字符的 `None` 仍作为 `None` 写回，不把“标题”字符串重复存入标签；
- 其他按钮来自 `active_role_names`，不显示“标题”、历史预设或未引用 N3 方案；
- 选择、拖选、Ctrl/Shift、Ctrl+A、新建角色及确定/取消语义保持不变。

## 6. 标题文字同步与模板固定

### 6.1 标题 Tab → 左侧列表

标题 Tab 修改 `text_template` 后：

1. 比较旧文字与新文字；
2. 迁移 `char_role_labels`；
3. 生成新的 `TitleOverlay`；
4. 刷新标题行适配器、角色列状态与预览；
5. 文字和迁移后的标签作为同一个 Style 修改进入撤销栈。

行数随换行即时增删。左侧逐字角色修改只改变标签，不反向改变标题文字。

### 6.2 文本差异迁移

迁移固定使用 `SequenceMatcher(autojunk=False)`：

- 把旧、新标题按字符展平，并把换行作为无标签边界 token 参与匹配；
- `equal` 块中的普通字符复制旧标签；
- `insert` / `replace` 产生的新字符标签为 `None`；
- `delete` 字符及其标签丢弃；
- 最后按新文字换行重建严格等长矩阵。

重复字符按算法给出的稳定 equal 块迁移，不进行基于语义的猜测。完全替换的一段
文字全部回到标题默认。

### 6.3 模板固定

若标题仍含 `{title}` / `{artist}`，左侧先显示当前元数据解析后的实际文字。用户
第一次打开标题逐字符编辑器时：

1. 使用当前主字幕元数据调用现有标题解析规则；
2. 把解析结果写回 `text_template`，移除模板动态性；
3. 生成/迁移标签矩阵；
4. 标题 Tab 立即显示固定文字；
5. 显示一次轻提示“标题模板已展开为固定文字”；
6. 再打开字符对话框。

若解析结果为空，不打开逐字编辑器，提示用户先在标题 Tab 输入文字。

## 7. N3 导入

### 7.1 基础标题方案

仍只导入第一个非空 `TitleInfos` 槽位。读取其中所有非 ruby 标题字符及
`FontIndex`：

- 统计全部非空白字符的 `FontIndex`；
- 出现次数最多者作为内置“标题”基础方案；
- 平票时选择最先出现者；
- 没有非空白字符时回退到第一个有效 FontIndex，再无有效值则使用默认标题方案。

基础字体方案转换后写入 `custom_style_schemes["标题"]`。

### 7.2 逐字符标签

- 使用基础 FontIndex 的字符写 `None`；
- 使用其他 FontIndex 的字符写对应 `LyricsFonts[].SettingsName`；
- 空格和分隔符同样保留自己的 FontIndex，因此样例 ` / ` 的 `情報小` 不丢失；
- 标题实际引用的非基础方案物化进 `custom_style_schemes` 并加入
  `active_role_names`；
- 未被歌词或标题引用的 N3 出厂方案可继续保存在样式数据中用于兼容，但不进入
  当前角色选择列表。

标题 ruby 不属于本次逐字符颜色范围，继续按当前标题导入能力处理。

## 8. 渲染

### 8.1 有效样式

- 标签为 `None`：使用“标题”方案；
- 标签为角色名：使用正常的角色方案解析规则；
- 角色方案缺失：回退“标题”方案；
- 标题永不走字，全部使用有效方案的“走字前”外观。

角色可逐字符改变字体、拉丁字体、字号、字重、斜体、填充、描边、二重描边、
发光和阴影。

### 8.2 排版与绘制

- 标题仍作为一个整体块使用统一 `layout_index`、对齐、显示时段和透明度；
- 每行先测量所有字符的有效样式，再计算整行宽度和块宽；
- 混合字号时行高和 baseline 按该行最大字形范围计算，避免裁切；
- 字符间距沿用逐字歌词规则，由前一个字符的有效方案决定；
- 按连续同方案字符切 run，分别绘制路径和装饰；
- 标题图层缓存 key 必须包含逐字标签和引用方案的有效样式签名，保证角色修改后
  立即失效重绘。

## 9. 撤销、预览与错误处理

标题文字和角色标签都位于 Style 内：

- 标题 Tab 文字修改及其标签迁移作为一个 Style 撤销单元；
- 一次逐字符对话框“确定”作为一个 Style 撤销单元；
- Ctrl+Z/Ctrl+Y 同时恢复标题文字、标签、列表状态和预览；
- “取消”不生成修改或撤销记录。

防御规则：

- 旧项目缺失矩阵时补全 `None`；
- 矩阵行数/字符数不匹配时通过迁移/规范化修正，不用 `zip` 静默截断；
- 不存在的角色标签在渲染时回退标题默认，并在规范化时清为 `None`，不向 UI
  暴露僵尸角色；
- 标题关闭时保留数据但不渲染；
- 所有用户可见提示使用中文。

## 11. 明确不做

- 多标题槽位列表化；
- 标题逐行独立布局；
- 标题走字和逐行特效；
- 标题 ruby 能力扩展；
- 在预览画布直接框选标题字符；
- 修改 SUG submodule。
