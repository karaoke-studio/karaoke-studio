`LyricsFontModel → SubtitleStyleScheme` 已抽到 `n3_font_scheme.py`，`.n3proj` 与 `.tpl`

## 3. N3 文件与对象结构

### 3.1 `.tpl` 保存位置

非 MSIX 版：

```text
%APPDATA%\SHINTA\NicoKaraMaker3\TemplateFont\<GUID>.tpl
```

MSIX 版：

```text
%LOCALAPPDATA%\Packages\<PackageFamilyName>\Settings\TemplateFont\<GUID>.tpl
```

`.tpl` 是 ZIP，内部固定读取名为 `0` 的 UTF-8 JSON。N3 选择窗口只显示
`Synchronize == true` 的模板，并按 `SettingsName` 排序。

### 3.2 顶层 `LyricsFontModel`

```text
LyricsFontModel
  BrushInfos[8]
  FontInfos[6]
  DecorKind
  DecorSize { Size, Reference, Ratio }
  BlurLevel
  SettingsName / Index
  Synchronize / SynchronizedTime
  CreateAppVer / ModifyAppVer
  Guid / LastModified
```

其中视觉字段是 `BrushInfos`、`FontInfos`、`DecorKind`、`DecorSize` 和
`BlurLevel`。其余字段用于模板名称、同步、排序和修改记录。

### 3.3 `FontInfos` 六个固定槽位

| 索引 | N3 `FontFacePage` | fallback |
|---:|---|---|
| 0 | 歌词/汉字 | N3 默认字体与默认数值 |
| 1 | 歌词/假名 | 0 |
| 2 | 歌词/英数 | 0 |
| 3 | ruby/汉字 | 0 |
| 4 | ruby/假名 | 3 |
| 5 | ruby/英数 | 3 |

本项目只导入 0/2/3/5 四个有效槽位。槽位 1 和 4 的字体族、字号、字重、描边及
二重描边全部忽略：主文字假名使用槽位 0，注音假名使用槽位 3，且不显示兼容警告。

每个槽位保存：

```text
FontName
FontFaceName
CharSize  { Size, Reference, Ratio }
EdgeSize  { Size, Reference, Ratio }
UseEdge2  bool | null
EdgeSize2 { Size, Reference, Ratio }
```

N3 的字符分类不是简单的 Python `isascii()`：

- 假名：平假名、片假名、`ー`、全角空格；
- 英数：ASCII `U+0020..U+007E`，以及 `À..ÿ`；
- 其他字符：汉字页；
- ruby 再整体偏移到索引 3～5。

### 3.4 `BrushInfos` 八个固定槽位

| 索引 | 含义 |
|---:|---|
| 0 | 走字后/文字 |
| 1 | 走字后/描边 |
| 2 | 走字后/二重描边 |
| 3 | 走字后/装饰（阴影或发光颜色） |
| 4 | 走字前/文字 |
| 5 | 走字前/描边 |
| 6 | 走字前/二重描边 |
| 7 | 走字前/装饰（阴影或发光颜色） |

每个笔刷同时保存所有编辑分支，但只有 `SelectedBrushTypeIndex` 指定的分支生效：

```text
0 Solid          -> SolidColor.DxColor RGBA
1 Gradient       -> GradientStops[{ Position, Color RGBA }]
2 MilleFeuille   -> GradientStops，N3 在边界位置复制前一颜色形成硬切
3 Bitmap         -> BitmapPath + BitmapScale
```

单向视觉导入只需保留当前生效分支；若未来要回写 N3 或在本项目中切换填充类型后恢复
N3 的未选中编辑值，则必须额外保存原始分支数据。

## 4. N3 的实际解析规则

### 4.1 字体族与字体面是成对 fallback

N3 从当前 `FontFaceInfoModel` 开始：

1. 如果 `FontName` 非空，直接使用该槽位的字体族和该槽位的 `FontFaceName` 所对应字重；
2. 只有 `FontName` 为空时，才沿 `Fallback` 继续查找；
3. 整条链字体族都为空时，使用 N3 默认字体并使用 Bold。

因此不能分别执行“找第一个非空 `FontName`”和“找第一个非空 `FontFaceName`”。旧
导入器曾分别解析两者，存在如下错误场景：

```text
英数 FontName = Comic Sans MS
英数 FontFaceName = 空
主文字 FontFaceName = Bold
```

N3 使用 Comic Sans MS Normal；旧导入器会把主文字 Bold 错误套给英数。当前共享解析器
已将字体族与字体面作为不可拆分的一组解析。

N3 的字体面列表只枚举 DirectWrite `FontStyle.Normal`，`FontFaceName` 在这里主要代表
字重，而不是斜体或 stretch。导入 N3 时应精确解析字重，并把斜体明确设为关闭，避免
项目全局斜体污染 N3 方案。

### 4.2 数值字段独立 fallback

`CharSize`、`EdgeSize`、`EdgeSize2` 分别沿各自 fallback 链查找第一个大于 0 的
`Size`。整条链都没有有效值时，N3 默认值为：

| 字段 | N3 最终默认值 |
|---|---:|
| `CharSize` | 100 |
| `EdgeSize` | 5 |
| `EdgeSize2` | 5 |

旧 `_resolve_font_size()` 在整条链无有效值时返回 0。当前共享解析器会物化上述最终值，
避免自定义 `SubtitleStyleScheme` 通过 0 或 `None` 错误继承另一个全局方案。

### 4.3 `UseEdge2` 是 nullable fallback

1. 当前槽位是 `true/false` 时立即使用；
2. `null` 时沿 fallback 链继续查找；
3. 整条链都是 `null` 时为 `false`。

当前共享解析器按这项规则物化开关，不能因为 `EdgeSize2.Size > 0` 就强制开启。

### 4.4 `.n3proj` 与 `.tpl` 的 `SizeAndRatio` 语义不同

#### `.n3proj`

工程文件中的 `Size` 已经由 N3 按工程画面高度更新。现有导入器直接读取 `Size` 是正确
行为，不应再次按 `Ratio` 缩放。

真实工程 `異世界ガールズ♡トーク/1.n3proj` 的画面高度为 1080，保存值也是：

```text
主文字 100 @ 1080
描边 15 @ 1080
ruby 45 @ 1080
装饰 5 @ 1080
```

所以当前读取结果与 N3 一致，并不能证明导入器已经实现了比例换算。

#### `.tpl`

N3 应用模板时会对 `DecorSize` 和全部六个 `FontInfos` 调用 `UpdateSizes(height)`：

```text
if target_height != 0 and Ratio != 0:
    Size = int(target_height * Ratio)
else:
    Size = 原值
```

例如现有“标准配色”模板保存 `CharSize=133, Reference=1440,
Ratio=0.092592...`，应用到 1080 高度后应得到 100，而不是 133。

### 4.5 模板跨分辨率复用

本项目 `StylePreset` 当前主要保存绝对像素值。如果 `.tpl` 在导入当前工程时直接折算为
绝对像素，再把预设应用到另一种画面高度，就不再具备 N3 模板的动态缩放语义。

需要明确选择并测试其中一种方案：

1. **完整对齐方案**：为导入的 N3 预设保留各尺寸的 `Ratio`，每次应用到项目时按当前
   画面高度解析；
2. **固定像素方案**：导入时按当前项目高度解析，后续跨分辨率不再缩放，并在导入界面
   明确提示。

本计划以完整对齐方案为目标。不能把模板原始 `Reference` 当作当前项目高度直接使用。

```text

  英数字体 = Comic Sans MS
```

### 6.1 Alpha 表示

本项目 `QColor`、属性面板和 Painter 已能处理 `#AARRGGBB`；N3 导入器也已使用同一
转换函数覆盖纯色、渐变 stop、MilleFeuille 和装饰色。颜色选择窗口另有可见的棋盘格
透明度条，并与 Qt Alpha 数值双向同步。转换规则为：

```text
A/R/G/B float 0..1
→ round(channel * 255)
→ #AARRGGBB（A=255 时可规范化为 #RRGGBB）
```

纯色、渐变 stop、MilleFeuille 和装饰色都使用同一转换函数。

### 6.2 渐变坐标、硬边与缓存

10.74.80.0 的 `BrushInfoModel.CreateBrush()` IL 已确认：Gradient 和 MilleFeuille
都建立从 `(0, 0)` 到 `(0, renderTarget.Size.Height)` 的纵向笔刷；调用点位于
`DrawOneCharBodyText`、`DrawOneCharEdgeText` 和 `DrawOneCharEdge2Text`。本项目因此以
字符或同样式 glyph run 的局部矩形 top→bottom 建刷，缓存 run 内字体度量相同，坐标
语义不会因合并缓存而变化。

MilleFeuille 的 IL 会在每个源 stop 后插入 `(next.Position, current.Color)`，并忽略
最后一个源 stop 的颜色。Qt 会合并同位置的 `QGradientStop`，所以不能直接照搬重复
stop；当前改为 `split_vertical` 真硬色带模型，并使用 1×目标高度的纹理逐像素保存
边界。基础纹理进入独立 LRU，缓存键包含目标高度、完整浮点位置和 RGBA；字符位置仅
对缓存笔刷副本做平移。`clear_before_layer_cache()` 会与文字层、发光层和图片笔刷一起
清除此缓存，`_fill_signature()` 也包含完整节点列表，样式变更不会命中旧烘焙层。

## 8. `.tpl` 导入功能清单

### 8.1 共享转换层

已新增独立于 Qt UI 的 `n3_font_scheme.py` N3 字体方案转换模块，职责包括：

1. 读取/校验 `LyricsFontModel` 字典；
2. 按 N3 规则解析 0/2/3/5 四个有效字体槽位，明确忽略假名槽 1/4；
3. 按入口类型处理尺寸：
   - `project_snapshot`：读取 `Size`；
   - `template`：按目标高度解析 `Ratio`；
4. 转换 8 个笔刷；
5. 输出完整 `SubtitleStyleScheme`，同时返回结构化 warning；
6. 由 `.n3proj` 导入器和 `.tpl` 导入器共同调用。

不要继续把所有逻辑保留在 `n3proj_import.py::_scheme_changes()` 内。

### 8.2 文件发现与读取

1. 自动发现普通版和 MSIX 版 `TemplateFont`；
2. 同时允许用户手动选择 `.tpl` 文件或目录；
3. ZIP 内只读取条目 `0`；
4. JSON 错误、缺少必要字段、GUID 与文件名不一致时分别给出中文错误；
5. 默认只列出 `Synchronize == true`；删除态模板可在诊断模式显示；
6. 按 `SettingsName` 排序；
7. 支持多选批量导入。

### 8.3 样式预设库接入

推荐入口是现有“样式预设库”，新增“从 N3 导入”操作：

1. 每个 `.tpl` 转为一个 `StylePreset`；
2. 默认分组可设为 `N3`；
3. 名称来自顶层 `SettingsName`；
4. 同名时提供覆盖、自动改名、跳过，并支持批量统一策略；
5. 导入预设不自动改动当前角色；导入完成后由现有“应用到当前目标”或“导入为项目角色”
   流程处理；
6. 单个模板失败不应取消整批，结束后显示成功/跳过/失败汇总。

### 8.4 预设持久化边界

当前 `_style_presets` 同时进入应用设置与 `.yurika` 项目快照。N3 预设额外保存
`source_type/source_data`，其中包含原始模板 JSON、Guid 和来源路径；因此导入一次后新项目
仍可使用，项目文件也保留当时的独立快照。

### 8.5 图片填充的延迟解析

N3 的 `BitmapPath` 优先相对歌词源文件目录解析，然后尝试绝对路径。导入器已通过原始
模板 JSON 保留路径；打开预设库时会使用当前歌词源目录延迟重算，确实不存在时才提示并
回退纯色。图片笔刷的平铺、缩放方向和纹理锚点精度仍属于 P2 待办。

## 9. 不参与视觉导入的字段

以下字段默认不进入 `SubtitleStyleScheme`：

| 字段 | 处理 |
|---|---|
| 顶层/子对象 `Guid` | 本项目创建自己的预设身份；可作为 source metadata 保留用于重复导入识别 |
| `Synchronize` | 仅用于过滤 N3 删除态模板 |
| `SynchronizedTime` | 不参与视觉 |
| `CreateAppVer/ModifyAppVer` | 可记录在诊断信息，不参与视觉 |
| `LastModified` | 不参与视觉 |
| `Index` | N3 UI 顺序字段，不参与视觉 |
| 子对象 `SettingsName` | 仅用于错误/警告上下文和 8 槽位诊断 |
| `DxColor.SumRGB/Average/Luma` | 派生值，只读取 R/G/B/A |
| 未选中笔刷分支 | 单向视觉导入可忽略；需要 N3 round-trip 时才保留 |

## 10. 本机真实数据审计

### 10.1 `TemplateFont` 四个模板

当前四个模板为：

- `【1配色】`
- `【2配色】`
- `【3配色】`
- `標準配色`

共同特征：

- 没有假名独立字体；
- 没有英数独立字号/描边；
- 所有颜色 Alpha 为 1；
- 没有 Bitmap 和 MilleFeuille；

因此这四个模板的首批阻塞项是 `.tpl` 读取、`SizeAndRatio`、渐变浮点位置，以及预设库
接入；其他字段仍必须用合成 fixture 锁定，不能因为四个样例没使用就省略检测。

## 13. 验收门槛

1. `.n3proj` 和 `.tpl` 使用同一个 N3 字体转换器；
2. 支持字段必须实际写入 Style、项目保存、UI 和 Painter，不能只解析不应用；
3. 不支持字段必须按字段值检测并给出中文提示，不能只检查 `FontName`；
4. N3 方案内部 fallback 不得泄漏到本项目全局方案；
5. `.n3proj` 不重复缩放，`.tpl` 必须按目标高度缩放；
6. `UseEdge2` 全链 null 时保持关闭；
7. 现有 N3 导入测试、模型/项目保存、属性面板和 Painter 测试全部通过；
8. 四个真实模板完成导入预览；三个真实 N3 工程完成回归；
9. 对渐变、MilleFeuille、Bitmap、Alpha 和脚本独立设置使用合成 fixture 补足真实样例空白；
10. 文档中的 ⚠️/❌ 项未完成前，不对外宣称“任意 N3 字体模板完全无损导入”。
