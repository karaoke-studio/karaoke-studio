# 粒子特效实现经验（下落 / 火焰 / 闪电）

> 2026-10 字幕渲染模块粒子特效多轮视觉迭代的交接笔记。
> 面向后续接手本模块的 agent：这里记录**架构约束、时序模型、设计口径、
> 验证流程和踩过的坑**，不是变更日志。改特效前先读完本文，再动代码。

---

## 0. 一句话结论

- **时序问题优先改粒子的时间轴并补渲染通道，不要挪文字。**
- **轨迹用纯函数 + AE 曲线 + 速度渐隐，不做“地面”和无限加速。**
- **随机性靠预设库 + 固定伪随机表，不用 `random`。**
- **散度不够时，同时加出生高度带、横向出生点、落点范围和摆幅。**
- **所有改动 CPU/GPU 双侧镜像，并以 GPU 实帧为验收口径。**

## 1. 模块地图与单一事实源

| 职责 | 位置 |
|---|---|
| 规划器 + 轨迹求值器（唯一事实源） | `krok_helper/subtitle_render/engine/render/effects/particles.py` |
| CPU（QPainter）消费端 | `krok_helper/subtitle_render/engine/painter.py`（`_paint_line_fx_particles`） |
| GPU（Direct2D）求值镜像 | `native/subtitle_renderer/src/backends/direct2d/d2d_fx.cpp` |
| GPU 行循环 / 预演 / 尾奏 | `native/subtitle_renderer/src/backends/direct2d/d2d_backend_render.cpp` |
| 粒子档位集合 | `krok_helper/subtitle_render/domain/timing.py` |
| 逐字过渡编排 | `krok_helper/subtitle_render/engine/render/elements/horizontal/transitions.py` |
| 扫字线特效规划/求值 | `particles.py`（`SCANLINE_FX_*` 常量、`plan_line_bursts` 末尾的 scanline 块、`burst_particles_at` 的 scanline 分支） |
| GPU 扫字线特效镜像 | `d2d_fx.cpp` 的 `burst.kind == "scanline"` 分支 |

关键纪律：

1. **burst 规划只在 Python 做**（`plan_line_bursts`），C++ 只消费场景 IR 里的
   `ParticleBurst`。不要在 C++ 里另建一套时序。
2. **sprite 只有 `FX_SPRITES` 一个来源**，随 IR 的 `fx_sprites` 下发；C++ 只按名字查表，
   不内置轮廓副本。
3. **轨迹常数必须双侧同步**：`particles.py` 与 `d2d_fx.cpp` 里的同名常量、哈希、
   曲线公式逐位一致，改一侧必须改另一侧，并在注释里互相点名。
4. 只改 Python 的典型后果：CPU 预览正确、GPU（用户主路径）错误。

## 2. 时序模型（最容易改错的部分）

### 2.1 burst 与逐粒子出生

- 每个 burst 有 `start_ms` / `end_ms`；寿命 `life = end - start`。
- 每颗粒子的出生延迟：

  ```text
  delay = spawn * life * (0.18 唱字 / 0.45 入场退场)
  spawn = 0 if (sweep > 0 and i == 0) else u3
  ```

  **入场 emitter 第一帧必须有一颗粒子**（`i == 0` 立即出生）。否则“粒子提前发射”的
  窗口里可能一颗都没生成，用户会认为提前量无效。
- 粒子在 `tau < delay` 时不存在；`p = (tau - delay) / (life - delay)`。
  **不要给 `p` 加预滚偏移**（`p = 0.2 + 0.8 * base`）——那会让粒子一出生就出现在
  轨迹中段，用户明确否决过。

### 2.2 行级错峰

- 单字内部已经有 0~45% 寿命的连续出生；但长行每字只差几十毫秒，整排仍会“一起落”。
- 用固化的 20 数相位表 `FALL_LINE_PHASES`：

  ```text
  start = base + min(900ms, 55% × life) × phase[char] + char_time_offset(char)
  ```

- 相位表**不要按字符序均匀推进**，否则看起来仍是规则波浪。
- 逐字还有 ±80ms 抖动表 `CHAR_TIME_OFFSETS_MS`。
- **2026-10-22 推广**：同一张相位表也用于非下落特效的逐字起点
  （音符/爱心/火焰/闪电，`_fx_line_start`）：这些档位的总错峰窗口不变
  （仍由 350ms 或「动画时长×7/12」决定），只把窗口内的顺序打散，
  长行不再读成规则波浪。

### 2.3 文字时序与粒子时序是两条独立时间线

- 文字逐字渐显窗口由 `entry_lead_ms` / `exit_fade_ms` 控制；粒子编排按标准速率独立播放。
- **不要为了让粒子先出现而延后文字渐显**。正确做法见 2.4。
- 退场保持“文字先消失、粒子后出现”，用户明确说这个观感适合下落特效，不要动。

### 2.4 显示窗之外的粒子：入退场分离通道

粒子允许画出显示窗：

- **入场预演**：显示窗开始前，下落风格入场粒子整体前移 20% 粒子寿命发射。
  - 提前量：`fall_entry_lead_ms(kind)`，花瓣/羽毛 340ms、雪花 400ms
  （2026-10-23 雪花出入场寿命 1500→2000ms 后同比增加）。
  - burst 的 `start_ms` 和 `end_ms` 一起前移。
- **退场尾奏**：显示窗结束后，退场粒子按完整寿命继续播到自然终点。

两条通道都**只画粒子**，文字/注音/发光/描边全部跳过。

Python 侧：

- items 选择：`_entry_particle_prelude_items` / `_exit_particle_tail_items`
- 绘制：共用 `_paint_particle_only_items`
- `paint_frame` 的“空内容早退”必须把这两类 items 算进去，否则会提前返回。

GPU 侧：

- `activeLines` 选择：`visible || exitTailBursts || entryPreludeBursts`
- 行循环里 `particleExitTail || particleEntryPrelude` 分支必须：

  ```cpp
  context->SetTarget(targetBitmap);
  context->SetTransform(identity);
  context->BeginDraw();
  if (!renderedAnyLine) context->Clear(transparent);
  // withViewport(Translation(dx, dy))
  drawFxBursts(false);
  drawFxBursts(true);
  EndDraw();
  renderedAnyLine = true;
  continue;
  ```

  **必须在 BeginDraw/EndDraw 内绘制并置 `renderedAnyLine`**。否则：
  - 空帧分支的 `EndDraw` 会报 `D2DERR_WRONG_STATE`；
  - 或粒子被后面的空帧 `Clear` 擦掉。

## 3. 运动设计（AE 口径）

### 3.1 下落曲线

- 三次 Hermite：`s(0)=0, s(1)=1`，初速 0.2、末速 0。
- 先加速、接近落点减速；`_fall_progress` / `_fall_velocity` / `_fall_speed_fade`
  三件套双侧镜像。
- 不要纯重力无限加速，也不要“地面/字底堆积”。
- 收尾用**速度渐隐**：速度越低越透明，落点速度 0 时 α=0。
- **不要另加尺寸缩小作为消失机制**。雪花曾用 `size × (1.05 - 0.40p)`，用户看到
  “落到底直接消失”，要求删除，改为和其他粒子一致的速度渐隐。
- **下落速度与 wipe 唱字速度无关**（2026-10-23 用户确认）：每颗粒子的寿命
  是效果常量（唱字档现为花瓣 1500 / 雪花 1600 / 羽毛 1700ms；雪花出入场
  2000ms），字窗只决定何时发射，不参与速度计算。快速段落额外的“下砸感”
  来自**每秒粒子密度**随字速率暴涨——唱字档用 `fall_sing_per_char` 按字窗
  长度收敛逐字颗数（基准 150ms、至少 1 颗）来保持每秒粒子量稳定，而不是
  改下落速度。回归测试：`test_falling_sing_speed_is_independent_of_wipe_speed`。

### 3.2 起始高度与落点

- 入场/退场/唱字统一从主文字上方起飘（约 0.55~1.25 `box_h`，按档位不同）。
- 落到字底附近或字框上方即按速度渐隐，不需要“看到落地”的观感。
- 入场/退场是两组独立粒子，**不要求高度连续**；退场不要统一从字底生成。

### 3.3 走字风

- 卡拉 OK 走字自左向右，下落粒子整体**向右后方漂移** + 固定后倾角：
  花瓣 -22°、雪花 -30°、羽毛 -32°。
- 不要绕中心点做大幅对称钟摆；只保留低频小扑动。
- 扑动频率锁在约 0.3~0.65 周期/寿命，去掉 2~3 周期的高频抖动。

### 3.4 散度（用户最敏感的一项）

雪花/羽毛曾因为“聚成团”被点名，花瓣是用户认可的参照物。有效手段：

1. **出生高度带**：至少 0.55~1.25 `box_h`（比花瓣更宽）。
2. **横向出生点**：`land_x ± 1.0 box_w` 量级的额外偏移。
3. **落点范围**：`land_x` 取 ±1.0 `box_w`，`land_y` 带 0.24~0.30 `box_h`。
4. **摆幅**：`size × (0.26 + 0.12u)` 量级。
5. 入场首颗粒子立即出生，保证提前量内一定看得到粒子。

### 3.5 尺寸与随机性

- 尺寸景深：`_fall_depth(depth_slot, count, u4)`，深度档按
  `(i + seed) % count` 轮换，避免每个字的最大粒子总落在同一个相对位置。
- 逐字 seed 用大奇数盐（`FALL_CHAR_SEED_SALT`），避免相邻字哈希序列过于接近。
- 所有随机量走 `fx_unit_hash(index, salt)` 的纯函数哈希：
  - CPU/GPU 逐帧一致；
  - 导出可复现；
  - **不要用 `random`**。
- “随机性不够”的解法不是调大振幅，而是：
  - 多套同风格 shape 预设（`FLAME_BODY_SHAPES`、`LIGHTNING_SHAPES`）；
  - 多尺寸档；
  - 固化伪随机模式表（`FLAME_SHAPE_PATTERN`、`LIGHTNING_SHAPE_PATTERN`）。

### 3.6 火焰 / 闪电的额外经验

- 火焰：多火形 + 多尺寸 + 点燃/熄灭冲击层（fireball / flash / shockwave / spark /
  glow），不要同一张剪影复制。
- 闪电：核心 bolt 前置、放大暗色辉光垫后；用 `stretch_y` 从锚点生长，不要整根闪现；
  默认黄白色；三套 bolt 预设 + 三档尺寸 + 频闪。
- 冲击层尺寸要克制：冲击环大了会占半屏，最终收敛到 1.5~2.0× 粒子尺寸。

### 3.7 非下落特效（音符 / 爱心 / 火焰 / 闪电）的同类改造（2026-10-22）

用户口径：这四档不是下落特效，但**随机性与丰富度**要向雪花/花瓣看齐。
下面几条是同一套经验在上升/原地型特效上的落地方式：

1. **多 sprite 预设 + 固定权重/伪随机表**（不是给同一张剪影换尺寸）：
   - 音符族 `NOTE_SHAPE_PRESETS = (note, note_dot)`——八分音符 / 附点音符，
     按 `NOTE_SHAPE_WEIGHTS = (1, 2)` **1:2 出现**（每字 3 颗 = 1 八分 + 2 附点；
     横梁双音符已按用户口径删除）；
   - 爱心族 `HEART_SHAPE_PRESETS = (heart,)`——**只保留原始 Twemoji 心形**
     （用户口径：不再做圆润/修长变体）。
2. **用大小变化提供丰富度**：`PARTICLE_DEPTH_TIERS = (0.55, 0.82, 1.12, 1.50)`
   四档 + `seed` 轮换 + 独立哈希抖动（约 2.7 倍档差）。尺寸与横向出生点
   彻底解耦——原先「尺寸系数」和 x 偏移共用 `u1`，最大的那颗永远偏向
   同一侧（即 §4.5 的「最大粒子总在同一位置」）。
3. **首颗粒子立即出生**：音符/爱心 `spawn = 0 if i == 0 else u3`，
   其余在 0~42% 寿命内错峰；逐颗行程/出生高度/摆幅频率各有独立通道。
4. **落雷簇状重击**：`LIGHTNING_STRIKE_BIRTHS`（固定表）给出
   「两三连击 → 停顿 → 补击」的真实闪电节奏，替代均匀随机出生；
   核心 bolt 与暗影辉光仍逐记重合。
5. **火簇抖动**：`FLAME_PUFF_OFFSETS`（±30% 簇间隔）+
   `FLAME_PUFF_SCALES`（0.82~1.16× 逐簇尺寸），火势不再像节拍器；
   「点燃冲击」锚到第一簇的抖动后起点（`flame_puff_start_ms`），
   否则冲击与火流会错开。
6. **走字火焰按 AE 多系统方案加厚**（出入场火焰保持原样，用户口径
   「燃烧的出入场没问题」）：参照 AE 火焰预置的常见拆法——**火芯/火舌 +
   火星 + 烟 + 光晕**分层、并给单颗粒子更碎的生命周期。落地为：
   - `smoke` 层（[smoke sprite]）：比火晚出生、慢升膨胀、低透明度、垫字后；
   - 唱字专用火星（`spark`，5 颗/簇）侧向飞散 + 下坠；
   - 火粒 `sweep == 2` 切到唱字运动学：寿命 0.45~1.0、尺寸 0.30~1.25 ×
     0.55~1.40、额外第三层高频湍流、向擦字反方向拖尾；
   - `emit_x`：按簇把发射点沿字符从左扫到右（-0.5~+0.5 × span × box_w），
     火团跟着卡拉 OK 擦字方向烧过去；IR 字段 `emit_x` 随 burst 下发，
     CPU/GPU 同口径（旧 IR 缺省 0）；
   - **走字火焰整体比原长火焰小 40%**（`FLAME_SING_SIZE_SCALE = 0.60`，
     只作用唱字档；尺寸/行程/背光/余烬/烟/火星同比缩放）——2026-10-22
     用户口径：火太大时几乎看不到走字。出入场火焰保持原样。
7. **逐字 seed 盐**：音符/爱心种子乘 `FALL_CHAR_SEED_SALT`（大奇数），
   避免相邻字的哈希序列过于接近。

新增 sprite / IR 字段时的额外护栏：

- sprite 轮廓仍是单一事实源（`FX_SPRITES` → IR `fx_sprites`），C++ 不内置副本；
- **Painter 的烘焙精灵缓存键必须是 sprite 名，不是 kind**——按 kind 缓存会让
  同一 kind 的不同造型全部复用第一张烘焙图（`_fx_baked_sprite_image`）；
- 新增 burst 字段（如 `emit_x`）要同时改：Python 规划器/求值器、
  `render_config.h` 的 `FxBurst`、`render_config_parser.cpp`、
  `gpu_scene_projection.cpp`、`render_types.h` 的 `ParticleBurst` 与
  `d2d_fx.cpp` 求值分支——漏一处就是 CPU/GPU 分歧或旧 IR 解析失败；
- 附点音符用「音符 + 不重叠附点圆」两条子路径：不重叠的独立子路径在
  even-odd / winding 下都是实心；**不要**用自交叠轮廓做新 sprite
  （旧 `note` 旗根有历史遗留的极细自交叠，新预设不要继承）。

## 3.8 扫字线特效（2026-10）

扫字线新增两条独立通道：**锋面粒子**（复用本模块的 burst）与**独立形态**（烈焰棒程序化图样 / 水泡粒子替换高亮带）。

### 3.8.1 锋面粒子

- **档位**：`sakura` / `feather` / `snow` / `snow_solid` / `star` / `note`，样式字段
  `scanline_effect`；只在 `karaoke_anim`（或反向档）为扫字线时生效，竖排与普通 Wipe 不发射。
- **规划**：每个字符一条 `kind="scanline"` burst（双色档按变体拆条）。新字段
  `emit_ms` = 字符唱字窗；burst 窗口 = `start + emit_ms + tail_ms`，尾部 tail 就是
  每颗粒子的固定寿命。颗数按 `scanline_particles_per_char` 以 300ms 为基准随字长缩放
  （至少 1 颗、最多基准 2 倍，默认基准只有 4 颗/字，避免长句铺满）。
- **求值**：出生延迟 `birth ∈ [0, emit_ms]`；`frac = birth / emit_ms`（RTL 取反）
  就是出生时的锋面横向进度，出生点 = 字框中心 + `(frac - 0.5) × box_w`。所有档位
  统一**朝左上飞**（LTR 向左、RTL 向右），形成与走字同向的速度感；樱花/羽毛/雪花
  保留自旋与扑动，不再向下飘落。
- **配色**：三类粒子颜色设置彻底解耦——入退场动画用 `anim_fx_*`、唱字装饰
  粒子用 `fx_particle_*`、扫字线粒子用 `scanline_effect_color_*`；属性面板
  用「入退场动画 / 唱字装饰粒子 / 扫字线特效」药丸切换当前编辑对象，各自
  独立保存。规划器通过 `particle_color_style(style, target)` 把目标字段投影成
  `fx_particle_*` 视图，颜色解析逻辑只写一份；旧版「入退场同用」开关在
  `style_from_dict` 里一次性迁移到 `anim_fx_*`。扫字线默认 `theme` 按档位
  主题色（樱花粉/羽毛白/雪花蓝白/星光金/音符白粉），其余模式与唱字粒子同语义。

### 3.8.2 独立形态（烈焰棒 / 水泡）

- 样式字段 `scanline_shape`：`band`（普通高亮带）/ `flame`（烈焰棒）/ `bubble`（水泡）。
  两者都是**独立形态**，会替换普通高亮带；不是把原高亮带换个颜色，也不是同一套柱状
  图样的两套贴图。
- **烈焰棒**：扫字线本体变成一根金色发光柱，四条火焰缎带以螺旋方式**环绕柱体**：
  前半圈压在柱身前，后半圈被柱身遮住、只从两侧露出；缎带宽度/相位逐帧摆动，
  不是贴在侧面的一排火舌。高度固定（约 1.65×行高，向上延伸覆盖注音层），呼吸时
  **只改外圈缎带绕柱半径**（约 ±5%），柱体宽高不变；RGB 先按预乘 alpha 合成、
  输出前再还原为直通颜色，并提亮背层，避免在深色文字上留下黑边/脏影。**棒体本身
  不发射粒子**，但「扫字线特效」仍可独立叠加。
  目标宽度约 `max(扫字线粗细×4.0, 行高×0.70)`，高度固定约 `1.65×行高`。
- **水泡**：真正的粒子形态，不再画柱状图样。CPU 在 `paint_scanline_bubbles` /
  GPU 在 `d2d_backend_render.cpp` 的 bubble 分支里，从锋面底部发射 18 颗水泡：
  中心一条浅蓝光柱（竖向透明→亮→透明渐变，延伸到注音层），偶数号水泡在光柱后、
  奇数号在前，形成前后遮挡；水泡 = 低透明水蓝填充 + 高光圆环 + 左上白色高光。
  **锋面正中仍保留一条水蓝色高亮扫字线**（正文高度，多层柔边），光柱只做背景，
  不会取代这条扫字线。
- **动画**：烈焰棒图样每帧按 `time_ms` 重新生成（缎带绕柱旋转/宽度呼吸，
  呼吸频率约 4.2 rad/s），高度不随呼吸变化；水泡完全由 `time_ms` 驱动，
  无静态图样。
- **性能**：烈焰棒内部栅格降到 72×108，缎带参数按行预计算、逐像素只做带状
  距离衰减；CPU 单帧生成约 5~6ms（128×192 逐像素版本约 15ms，会吃掉 60fps
  整帧预算）。GPU 同样按行预计算，避免每像素三角函数。
- **层次**：柱体不是字形内部高亮带，必须盖在文字层、文字动画层与注音层之上。
  CPU 在 `_paint_scanline_shape_overlay` 里于 `paint_rubies_on_top()` 之后统一
  绘制；GPU 把烈焰棒/水泡包进 `drawScanlineShapes` lambda，在 ruby 循环结束
  后、恢复基础变换前调用，避免 ruby 走字把柱体遮住。
- **配色**：烈焰棒/水泡共用一套三色推导：**外沿=基色，内焰=基色提亮 40%/55%，
  火芯=基色提亮 80%/85%**。基色来源：`default` 档固定出厂火色/水蓝；`color` 档
  就是 `scanline_color`（纯白即纯白，不再套默认）；`brighten`/跟随字体取当前字符
  自己角色方案的走字前/后主文字填充；`role` 取来源填充。渐变/拼色不再折平均色，
  而是按**整行**消费：横向渐变用柱体当前画布 x 在整行（音量柱启用时从柱组左缘
  起算）内的占比取色，柱体随锋面移动换色；纵向渐变按柱体自身高度取色。填充被
  烘成逐像素颜色场；图片填充暂取平均色。CPU 与 GPU 必须用同一套基色与颜色场推导。
- **中心高亮棒**：烈焰棒/水泡的中心不再使用程序化直线柱，而是**普通扫字线高亮带**
  按字形 geometry / feather / 角色配色绘制（CPU 在字形 pass，GPU 复用原 band
  绘制），所以会随字形轮廓裁剪。外围的火焰缎带/水泡/光柱保留，在 ruby 之后
  补画；柱体 fade 同时乘到中心带上。火焰缎带之间再叠一层无硬边、低透明度的
  实体光晕（内焰色为主），避免只看到细火舌、缺少体积。
- **淡入淡出**：柱体不再跟着文字逐字出现，开场约 160ms 淡入；淡出锚点取
  **最后一个字符的结束时间**（不是显示窗口 end-220ms），最后一个字唱完才开始
  220ms 淡出，最后几个字很快时也不会提前消失。CPU 在
  `_paint_scanline_shape_overlay` 乘 fade，GPU 用
  `displayWindows` + 最后 `char.endMs` 算同一包络。
- **柱高与 ruby**：柱体顶部不再固定 `center-0.62×height`，而是取本行所有
  ruby 的 `baseline-ascent` 最上沿再向上留 0.2 字号的余量；有注音时按需增高，
  保证火焰/气泡盖过注音最外沿，不出现“差一截”。
- **AE 参考**：AE 火焰通常用 Fractal Noise（持续提高 Evolution、向上 Offset）+ Turbulent
  Displace / Wave Warp 做不规则边缘，再用 Colorama / 渐变映射压成红→橙→黄→白芯，
  最后叠 Glow；呼吸感来自外焰半径/发光强度的慢速包络，燃烧感来自噪声向上滚动和
  高频闪烁。本实现没有引入 AE/第三方插件，用多层正弦湍流 + 逐帧旋转/上卷噪声近似
  这些层次，见 [Adobe Video World 火焰教程](https://adobevideoworld.com/fire-effect-after-effects/)
  与 [AE 参考手册 Turbulent Displace](https://help.adobe.com/archive/en/after-effects/cc/2013/after_effects_reference.pdf)。
- **验证**：`tests/test_subtitle_render_scanline.py` 覆盖档位序列化/旧值升级、规划窗口/
  颗数、锋面出生点（含 RTL）、左上飞行、六档 painter 可见性、烈焰棒/水泡的 CPU/GPU
  实帧与逐像素确定性、光柱蓝色/透明度、IR 字段与配色方案取色。

## 4. 用户口径（硬约束，不要重新发明）

1. “粒子先生成、文字后渐显”= **粒子提前发射**，不是文字延后。
2. “粒子刚生成有不动的时间”不可接受：出生即运动，首颗粒子立即出生。
3. “生成高度不对”= 粒子不能一出生就在轨迹中段；起点必须是各自的生成高度。
4. “整块同时从同一高度生成”不可接受：连续错峰出生 + 行级伪随机相位。
5. “每个字的最大粒子总在同一位置”不可接受：逐字 seed 盐 + 深度档轮换。
6. 雪花/羽毛的散度要和花瓣看齐甚至更大；花瓣是参照物。
7. 雪花不要单独的缩小/提前消失机制，和其他粒子一样按速度渐隐。
8. 退场时序不要改：文字先消失、粒子后出现。
9. 所有用户可见字符串中文；不改 SUG submodule；不建新分支。
10. 用户的最新口径覆盖旧口径。决策反转要在代码注释/提交信息里写清楚，
    不要偷偷保留旧行为。

## 7. 本模块演进中的关键反转（避免走回头路）

1. **终端速度曲线**（0.1→1.2 封顶）被否：没有飘落感。
   → 回到 AE 的“初速 0.2 + 末速 0”二次曲线。
2. **落地堆积**被否：要求落到不可观测处按速度渐隐。
3. **轨迹预滚**（`p = 0.2 + 0.8 × base`）被否：粒子一出生就在轨迹中段。
4. **文字渐显延后**被否：文字窗口必须保持原样，改为粒子整体前移 + 入場预演通道。
5. **雪花尺寸缩小淡出**被否：改为与其他粒子一致的速度渐隐。
6. **整排同时生成**被否：连续错峰出生 + 行级伪随机相位。
7. **每字最大粒子位置固定**被否：逐字 seed 盐 + 深度档轮换。
