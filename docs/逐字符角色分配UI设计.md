# 逐字符角色分配 UI 设计

> 2026-07-12 定稿并实施。角色系统背景见 `字幕渲染模块-需求设计.md` §0.3。

## 1. 背景与现状

渲染层的逐字符角色链路早已完整（Phase 3 完成）：`TimingChar.role_label` →
`_style_for_role` 逐字符合成有效 Style → `_build_text_layout(inline_styles=True)`
逐字符排版 → 按同角色连续段切 run 独立绘制。字号/字体/颜色/描边/发光/注音
逐字符混排均可渲染。

但 UI 上**没有逐字符操作入口**：

- 歌词列表「角色」列下拉是**整行**语义——`_on_lyrics_role_changed` 把该行所有
  字符的 `role_label` 覆盖成同一个值；
- 逐字符粒度只能靠字幕源文本 `【N配色】` 标签或 N3 导入的逐字符 `FontIndex`；
- 隐患：对 N3 导入的混合角色行使用行级下拉，会把行内逐字符分配整行抹平，
  且角色列显示的是「出现最多的角色」（`_dominant_role`），看不出行内混合。

产品决策（2026-07-12 与用户确认）：**逐字符只分角色，不做逐字符排版**；
需求文档 C6 的"免建角色单句 Style 快照"不做，统一走角色系统。

## 2. 交互设计

### 2.1 入口

1. 歌词列表右键菜单（单行选中且非空行）→「逐字符分配角色…」；
2. 内容列**双击**同样打开（特效列双击开逐行特效编辑器，同一习惯）。

角色列双击仍是原有的整行下拉（快捷路径不变）。

### 2.2 行内角色编辑器（模态对话框）

```
┌─ 逐字符角色 · 第 7 行 ──────────────────────────┐
│  [な][ん][で][願][い][は][届][か][な][い]        │  ← 字符块流式排布，自动换行
│   ●粉  ●粉  ○   ○   ○   ○   ○   ○   ●蓝  ●蓝    │     块底色 = 角色代表色（浅）
│                                                  │
│  分配为： [○全局默认] [●裏声] [●青配色] [＋新建] │  ← 点按钮应用到选中块
│                                        [取消][确定] │
└──────────────────────────────────────────────────┘
```

- **字符块**：每字一块，大号字体绘制，底色取角色方案代表色
  （`_scheme_swatch_color`，同角色列色点），无角色为中性底；
- **选择**：按下并拖动 = 连续范围选择；Ctrl+点击 = 离散增删；
  Shift+点击 = 锚点到当前的范围；全选快捷 Ctrl+A；
- **应用**：点下方角色按钮立即把选中块换成该角色（块底色即时更新，
  所见即所得）；「＋新建」输入名字后创建并立即应用；
- **确定**：返回逐字符标签列表，宿主写回；**取消**不产生任何修改。

不选中任何块时角色按钮禁用（避免误触整行）。

### 2.3 角色列的混合态

- 行内出现 ≥2 个不同角色（含"无角色"与具名角色混合）时，角色列显示
  「混合」+ 双色点图标（取行内前两种代表色各半圆）；
- 混合行使用整行下拉时弹确认框：「该行包含逐字符角色分配，整行覆盖为
  “X”？」——取消则还原下拉显示，不写回。

## 3. 数据流与撤销

```
_CharRoleDialog ──确定──▶ LyricsPanel.charRolesChanged(row, labels)
                                    │
             SubtitleRenderWindow._on_lyrics_char_roles_changed
                                    │
   逐字符写 role_label ─▶ 新角色名物化方案（预设库命中→深拷贝；
                          未命中→ set_roles 触发 _ensure_role_schemes 自动建）
                                    │
   撤销栈 push ("char_roles", track_index, row, old_labels, new_labels)
                                    │
   重喂预览（set_track / extra）＋ refresh_row_role ＋ 标脏
```

- 撤销命令与轨道时间/逐行特效/样式共用同一 Ctrl+Z / Ctrl+Y 栈；
  `_restore_char_roles` 直接写回标签（不经信号，避免二次入栈）；
- **行级下拉**改动也换用同一命令入栈（原先行级改角色不可撤销，顺带补齐）；
- 项目/字幕源切换时撤销历史照常清空（既有行为）。

## 4. 实现落点

| 位置 | 内容 |
|---|---|
| `frontend/lyrics_list.py` | `_CharChipsView`（自绘字符块 + 选择交互）、`_CharRoleDialog`、右键/双击入口、`charRolesChanged` 信号、混合态显示与覆盖确认 |
| `frontend/main_window.py` | `_on_lyrics_char_roles_changed` 写回 + 物化 + 撤销；`_restore_char_roles`；`_undo_edit`/`_redo_edit` 分发 `"char_roles"` 命令 |
| `tests/test_subtitle_render_lyrics_list.py` 等 | 对话框选择/应用逻辑、信号载荷、混合态显示、撤销重做回归 |

不改动：模型（`role_label` 已存在）、渲染、序列化（`.yurika` 已保存
`char_role_labels`）、N3 导入。

## 5. 明确不做

- 逐字符排版参数（字间距/咬合等仍是 全局 < 布局 < 角色 的方案域）；
- 需求文档 C6 的免建角色单句快照（被本方案取代）；
- 预览画布内直接框选字符分配（后续增强，等本入口用顺再评估）。
