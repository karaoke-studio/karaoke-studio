# 字幕段页、逐页布局与加载设置改造计划

> 状态：需求已于 2026-07-25 与用户逐项对齐并完成实现；本文同时作为兼容边界、
> 消费端清单和后续回归基线。
>
> 本文是本专项的数据模型、兼容迁移、消费端改造、UI 交互与验收计划。总体产品边界见
> [`字幕渲染模块-需求设计.md`](字幕渲染模块-需求设计.md)，N3 布局语义见
> [`字幕布局-N3对齐改造计划.md`](字幕布局-N3对齐改造计划.md)。

## 0. 目标与约束

本专项把当前“根据逐行 `layout_index`、`break_before` 和样式参数临时推算页面”的模型，
升级为项目明确保存的“段 → 页 → 歌词行”结构，并完成以下产品能力：

1. 歌词列表增加“布局”列，直接显示每一页实际使用的布局；
2. 按页单独或多选批量设置布局；
3. 只改变分页、不改变歌词顺序地移动页边界，后续歌词自动向前或向后流动；
4. 显式保存每段的页面集合、每页实际行数和布局引用；
5. 增加字幕源刷新按钮和独立的加载字幕设置浮出面板；
6. 支持全局加载默认值，以及主字幕/每个副字幕源的独立覆盖；
7. 保存加载设置后自动刷新并重建段页；
8. 旧 `.yurika`、N3 导入、实时预览、时间轴和 MP4 导出保持兼容且结果一致。

硬约束：

- 歌词行的原始顺序永远不因分页编辑改变；
- 页面实际行数与布局容量均为 1～8；
- 页面可以使用容量大于实际行数的布局，不能使用容量更小的布局；
- CPU QPainter 继续作为预览和导出的 oracle/fallback；
- 不修改 `krok_helper/lyrics_timing/` submodule；
- 用户可见字符串、Tooltip、提示和冲突报告一律使用中文；
- 按仓库规则直接在当前分支工作，不创建新分支。

## 1. 已确认的产品语义

### 1.1 段、页和轨道

- 每个字幕源有独立的段页计划；
- 一段包含一个或多个页面；
- 一页保存实际歌词行数和一个布局引用；
- 歌词按源文件中的有效行顺序依次流入段和页；
- 页内轨位显示为 `T1`～`T8`，不在轨列重复显示页号；
- 空页自动删除，空段自动删除，编号保持连续；
- 没有有效歌词时，段页计划为空，不伪造空的 `S1/P1`。

歌词列表中的虚拟提示行采用：

```text
♪♪♪ S1 ♪♪♪
♪ S1 · P1 ♪
T1  第一句
T2  第二句

♪ S1 · P2 ♪
T1  第三句
T2  第四句
```

提示行只属于 UI，不进入歌词源、预览、导出或逐行兼容数组。段内页号从 `P1` 重新开始。
若启用“空行开始新段落”，触发分段的连续空行折叠进段落提示，不再额外重复显示孤立的
`♪`；未启用时，源空行仍按现状显示为普通间奏 `♪`。

### 1.2 分段和分页

加载时按以下优先级构建：

1. 源文件显式 `paragraph`：开始新段；
2. 启用空行分段时，连续空行：开始一个新段；
3. 启用时间分段时，演唱空隙超过阈值：开始新段；
4. 源文件显式 `page`：开始同段新页；
5. 每段内按“每页基础行数”继续分页。

时间空隙严格定义为：

```text
下一句真实演唱开始时间 - 上一句真实演唱结束时间 > 分段间隔
```

提前显示、结束延时、动画时长和 lane 间隔不参与这个判断。

“每页基础行数”始终生效，范围 1～4。最后一页或显式边界前的页面允许不足该值，并按
实际行数选择项目默认布局。用户手工编辑后，单页可以扩展到最多 8 行。

### 1.3 手工边界编辑

只允许改变分页，不允许重排歌词：

- 将下一页第一行并入上一页：上一页增加一行，后续行自动向前补；
- 将当前页最后一行移至下一页：当前页减少一行，后续页面重新流动；
- 普通中间行不能通过拖动改变歌词顺序；
- 默认不允许跨段拖动；段落合并/拆分使用独立操作；
- 一次操作影响的全部页面重排作为一步撤销/重做。

右键操作：

- 在此行前插入分页；
- 删除此分页；
- 在此行前插入分段；
- 删除此分段。

删除分页会与同段上一页合并；删除分段只移除段落边界，原段第一页仍保留为普通页边界。
段落 `P1` 不能单独删除，需先删除该段的段落边界。删除分页后若没有任何布局能容纳合并
结果，应拒绝并提示先创建更大的布局。

### 1.4 页面布局

项目内始终有 1～8 行默认布局，并有明确的“行数 → 默认布局稳定 ID”映射：

| 行数 | 默认水平对齐 | 默认行间距 |
|---:|---|---:|
| 1 | 中 | 90 px |
| 2 | 左、右 | 90 px |
| 3 | 左、中、右 | 60 px |
| 4 | 左、右、左、右 | 40 px |
| 5 | 左、右、左、右、左 | 25 px |
| 6 | 左、右、左、右、左、右 | 15 px |
| 7 | 左、右、左、右、左、右、左 | 8 px |
| 8 | 左、右、左、右、左、右、左、右 | 0 px |

其他布局字段从当前项目默认布局继承。默认映射可改为另一个同行数布局；正在担任某行数
默认的布局不能在没有替代项时删除。

页面有 N 行时：

- 容量 `< N` 的布局禁用，并说明不能容纳；
- 容量 `>= N` 的布局可用；
- 自动分配始终选择 N 行项目默认布局；
- 用户选择更大布局时只更新页面的 `layout_id`，不额外记录或持久化布局来源。

短页使用更大布局时：

- Bottom 使用最后 N 个轨位；
- Top 使用最前 N 个轨位；
- Middle 使用居中的连续 N 个轨位；
- 无法绝对居中时优先靠下。

布局从 M 行缩小为 N 行时不阻止修改，但修改前提示受影响页数和预计新增页数。引用它且
实际行数大于 N 的页面降为 N 行，并在段内向后重排；必要时新增页面，零行页面自动删除。
若该布局原是 M 行默认布局，M 行默认恢复为内置 M 行布局。布局扩容不主动拉入后续歌词。

### 1.5 移动页面边界时的即时布局判断

不新增 `layout_origin`、`manual` 或同类持久化状态。每次拖动开始前，仅根据受影响页面当时
的布局容量和实际行数临时判断：

- `布局容量 > 页面实际行数`：视为用户有意选用了较大布局；
- `布局容量 = 页面实际行数`：视为普通匹配状态。

拖动完成后分别处理来源页和目标页：

1. 拖动前已使用较大布局，并且该布局仍能容纳拖动后的行数：保留原布局；
2. 拖动前布局容量等于实际行数：行数变化后切换为新行数的项目默认布局；
3. 拖动前已使用较大布局，但拖动后不再能容纳：切换为新行数的项目默认布局；
4. 页面变成 0 行：自动删除，并继续规范化空段和编号；
5. 未受页边界移动影响的页面保持不变。

判定必须使用拖动前的快照，不能在拖动后反推，也不能把推断结果写入项目。示例：

- 2 行页 + 2 行布局，增至 3 行：切换 3 行默认布局；
- 2 行页 + 4 行布局，增至 3 行：保留 4 行布局；
- 2 行页 + 4 行布局，增至 5 行：切换 5 行默认布局；
- 3 行页 + 3 行布局，减至 2 行：切换 2 行默认布局；
- 3 行页 + 4 行布局，减至 2 行：保留 4 行布局。

这条规则既避免普通页面在移动后留下不匹配布局，也无需维护容易失真的布局来源状态。

## 2. 新运行时模型

### 2.1 持久化/运行时 dataclass

建议在 `models.py` 增加以下概念（最终命名可按代码风格微调）：

```python
@dataclass
class SubtitleLoadingSettings:
    time_gap_section_enabled: bool = True
    section_gap_ms: int = 3100
    blank_line_section_enabled: bool = True
    rows_per_page: int = 2


@dataclass
class TrackPage:
    line_count: int
    layout_id: str


@dataclass
class TrackSection:
    pages: list[TrackPage]


@dataclass
class TrackPagePlan:
    sections: list[TrackSection]
```

`line_count` 是页面当前实际容纳的有效歌词行数，不是布局容量。规范化后的所有页面均满足
`1 <= line_count <= 8`，且所有页的 `line_count` 总和等于轨道有效歌词行数。

`TimingTrack` 增加可选 `page_plan`。解析裸 `.sug/.lrc` 时可以暂为空；进入字幕渲染项目
后由加载规则、N3 显式边界或旧项目迁移生成。副字幕源同样使用自己的 `TimingTrack.page_plan`。

### 2.2 稳定布局引用

`LyricsLayout` 增加稳定 `layout_id`。`Style` 自身的默认布局使用保留 ID（例如
`"default"`），额外布局使用持久化 ID。项目增加：

```json
{
  "default_layout_by_row_count": {
    "1": "builtin-1",
    "2": "default",
    "3": "builtin-3",
    "4": "builtin-4",
    "5": "builtin-5",
    "6": "builtin-6",
    "7": "builtin-7",
    "8": "builtin-8"
  }
}
```

旧数字索引继续作为兼容投影，不再作为新版页计划的权威引用。新增默认布局只能追加到旧
`style.layouts` 末尾，不能插到前面导致旧索引漂移。

### 2.3 唯一页面解析器

新增纯业务模块（建议 `engine/page_plan.py`），统一提供：

- 从加载设置和源显式边界构建计划；
- 从旧逐行字段迁移计划；
- 规范化空页/空段、范围和悬空布局；
- 解析为 `ResolvedSection/ResolvedPage/ResolvedLine`；
- 插入/删除页段边界；
- 移动页边界并顺序回流；
- 布局缩容后的段内重排；
- 生成旧 `layout_index/break_before` 投影；
- 计算受影响页面与提示摘要。

`ResolvedLine` 至少包含：

```text
track_line_index
render_line_index
section_index
page_index_in_section
global_page_index
lane
page_line_count
layout_id
```

所有消费端必须读取这一个解析结果，不能继续各自调用不同的分页算法。

## 3. `.yurika` 与旧项目兼容

### 3.1 Schema v2

项目 schema 从 1 升到 2，主字幕新增：

```json
{
  "page_plan": {
    "sections": [
      {
        "pages": [
          {
            "line_count": 2,
            "layout_id": "default"
          }
        ]
      }
    ]
  },
  "loading_settings_mode": "global",
  "loading_settings_snapshot": {
    "time_gap_section_enabled": true,
    "section_gap_ms": 3100,
    "blank_line_section_enabled": true,
    "rows_per_page": 2
  },
  "default_layout_by_row_count": {
    "1": "builtin-1",
    "2": "default",
    "3": "builtin-3",
    "4": "builtin-4",
    "5": "builtin-5",
    "6": "builtin-6",
    "7": "builtin-7",
    "8": "builtin-8"
  }
}
```

自定义源设置使用 `loading_settings_mode: "custom"` 和 `loading_settings`。主字幕与每个
`extra_subtitle_sources` 分别保存设置和页计划。

保存时继续双写：

- `line_layout_indices`
- `line_breaks_before`

旧版忽略新字段后仍能读取兼容投影。新版读取 `page_plan` 时以它为权威。

### 3.2 旧项目迁移

打开旧项目时：

1. 加载字幕源；
2. 先恢复已保存的 `paragraph/page`，不使用新规则重算；
3. 恢复旧 `line_layout_indices`；
4. 用旧分页语义读取当时实际页面；
5. 只有未保存的自动段落边界，才用旧 `Style.section_gap_ms` 补齐；
6. 从实际结果生成内存 `page_plan`；
7. 旧页面内若出现多个布局索引，在布局变化处拆页并显示兼容提示，不能静默丢布局；
8. 补齐 1～8 行默认布局时只追加，不重排旧布局；
9. 生成 `custom` 兼容加载设置，默认不跟随新全局设置；
10. 仅在用户保存时写成 schema v2，单纯打开不改磁盘。

更早的 schema v1 项目可能尚未保存 `line_breaks_before`。此时必须只在内存迁移阶段
重放当时 LRC 入口使用的 N3 `SeqLinesBreaker`（默认两行一页），再生成
`page_plan`；不能直接按当前所选布局容量合页，否则使用较大布局的旧页面会丢失原分页，
也就无法按新交互移动边界。已有完整旧边界数组时始终以保存值为准，不重新推断。

旧项目迁移后的刷新参数优先使用旧 `Style.section_gap_ms`；空行分段默认关闭，避免旧的
视觉空行突然改变段落。用户可主动切换到全局设置。

### 3.3 恢复、备份和外部修改

正式保存、自动恢复快照、手工备份和丢弃修改备份全部复用同一项目 payload，必须覆盖新
字段。项目外部修改检测仍按整个文件摘要工作，无需改变。

## 4. 加载设置与刷新

### 4.1 全局与逐源设置

`AppSettings.subtitle_render` 增加：

```json
{
  "subtitle_loading_defaults": {
    "time_gap_section_enabled": true,
    "section_gap_ms": 3100,
    "blank_line_section_enabled": true,
    "rows_per_page": 2
  }
}
```

每个字幕源可选择：

- 使用全局加载设置；
- 为此字幕源单独设置。

切换到单独设置时复制当前全局值。即使使用全局设置，项目也保存最近一次有效值快照，
用于解释既有页面计划和跨机器诊断；正常打开项目不因全局设置变化自动重排。

保存当前源设置后自动刷新当前源。保存全局设置后，自动刷新当前项目中所有跟随全局的
字幕源，并作为一个复合事务。

### 4.2 刷新事务

独立刷新按钮使用已保存的有效设置刷新当前源。刷新流程：

1. 读取并解析候选字幕；
2. 用 `source_reload` 的文本匹配保留角色、特效、导唱符和显示窗口覆盖；
3. 按最新加载设置重新生成段页；
4. 每页按实际行数选择项目默认布局；
5. 规范化空页/空段；
6. 全部成功后一次性替换当前状态；
7. 刷新歌词表、预览、时间轴、布局警告和导出模型；
8. 失败时完整保留旧状态；
9. 成功结果作为一步撤销，redo 使用已解析快照，不重新读取磁盘。

全局刷新多个源时使用一个复合撤销命令。

若存在手工分页、分段或逐页布局修改，刷新前显示影响摘要并确认；纯自动状态直接刷新。
冲突报告沿用文本匹配的可靠性原则，不能把旧的逐字角色或行内导唱符错误套到其他歌词。

### 4.3 LRC 规则迁移

新的加载路径不再在 `parse_nicokara_lrc()` 内提前固化 3100 ms/两行边界；解析器只恢复
源语义，段页构建交给加载设置。为兼容旧调用和测试，可以保留显式 legacy helper，但新
项目入口不得先生成旧边界再应用新设置。

N3 导入继续精确保留 `PageBreak/ParagraphBreak`，随后投影成新页面计划；SUG 空句继续
保留，是否触发新段由加载设置决定。

## 5. UI 方案

### 5.1 字幕源工具栏

排列为：

```text
[主字幕 ▼] [＋] [－] [刷新] [设置]
```

刷新使用刷新图标；设置使用齿轮图标。刷新期间显示忙碌状态并禁止重复触发。

设置按钮打开独立的右向浮出卡片，不进入角色/布局/时间等普通属性页。卡片包含：

- 设置范围：使用全局 / 当前字幕源自定义；
- 按演唱空隙分段；
- 分段间隔；
- 空行开始新段落；
- 每页基础行数 1～4；
- 编辑全局设置；
- 取消 / 保存。

保存设置必定自动刷新。取消丢弃草稿且不刷新。存在未保存草稿时点击面板外部需确认。

### 5.2 Tooltip 文案要求

“按演唱空隙分段”：

> 比较相邻两句的真实演唱时间。当“下一句开始时间 − 上一句结束时间”大于设定值时，
> 从下一句开始新段落。提前显示、结束延时和动画时长不参与计算。保存加载设置或点击
> 刷新后重新计算，并覆盖现有手工分页。

“分段间隔”：

> 自动分段使用的演唱空隙阈值，单位为毫秒。例如上一句在 10.000 秒结束、下一句在
> 14.500 秒开始，空隙为 4500 毫秒；阈值为 4000 毫秒时会开始新段落。仅在“按演唱
> 空隙分段”启用时生效。

“空行开始新段落”：

> 启用后，字幕源中的一个或多个连续空行会在下一条有效歌词前开始新段落。空行不占用
> 字幕轨道，也不计入每页行数。关闭后，空行只保留为视觉间奏标记，不影响段落和分页。

“每页基础行数”：

> 在每个段落内按照指定行数依次建立页面，范围为 1～4。源文件中的显式分页仍会提前
> 结束当前页；段落最后一页或显式分页前的页面允许不足指定行数，并自动使用对应行数
> 的项目默认布局。

刷新按钮：

> 使用已保存的加载设置重新读取当前字幕源，并重新生成段落、页面和默认布局。歌词
> 角色、逐行特效、导唱符及手动显示时间会在能够可靠匹配时保留；手工调整的分页将被
> 覆盖。

设置按钮：

> 设置字幕源的分段和分页方式。加载设置独立于字体、颜色、位置等渲染样式；保存后会
> 自动重新加载受影响的字幕源。

### 5.3 歌词表展示行适配层

当前大量代码假设 `QTableWidget.row == track.lines` 索引。加入虚拟段/页提示行后必须先
建立显式展示模型，例如：

```text
LyricsPresentationRow
  kind: lyric | source_blank | section_marker | page_marker
  track_line_index: int | None
  section_index: int | None
  page_index: int | None
  lane: int | None
```

所有点击跳转、角色菜单、逐字编辑、特效、多选、导唱符、标题模式和刷新局部行逻辑必须
通过适配层转换，信号继续发送 `track.lines` 索引，不能发送表格展示行。

提示行跨五列显示，不可进入歌词编辑操作。标题模式不显示段页提示，也不参与页面计划。

### 5.4 布局列和批量应用

表格扩为：

```text
轨 | 角色 | 特效 | 内容 | 布局
```

内容列继续 Stretch；布局列在内容右侧，按名称测量并设置上限。每一条歌词行都显示所在页
布局名称。

单击布局单元格或右键“应用布局”：

- 把所选歌词行去重为页面集合；
- 同一页只处理一次；
- 候选布局容量必须不小于所选页面的最大行数；
- 小布局置灰，并说明哪一页无法容纳；
- 同一次多选作为一步撤销；
- 混合状态显示“多个布局”；
- 悬停说明将影响多少页和多少行；
- 选择后只更新各页的 `layout_id`；后续拖动是否保留该布局，由拖动前的容量比较即时判断。

### 5.5 页面与段落交互

- `♪ Sx · Py ♪` 可选中整页；
- `♪♪♪ Sx ♪♪♪` 可选中整段；
- 拖动页首到上一页末尾，或拖动页尾到下一页；
- 拖动时高亮目标边界并预览“目标页将变为 N 行”；
- 禁止通过中间行拖动重排歌词；
- 禁止直接跨段拖动；
- 右键提供插入/删除分页与分段；
- 所有变化即时更新布局列、轨位、提示编号、斑马纹、预览和时间轴。

### 5.6 布局页按钮

- “应用到全部行”改为“应用到全部页”；
- 若当前布局不能容纳任一页面，按钮禁用并说明最大页面行数；
- “按行数自动分配”改为“各页使用默认布局”；
- 后者不重新分页，只按页实际行数恢复 1～8 行默认映射。

现有普通属性中的“分段间隔”移入加载设置。`Style.section_gap_ms` 仅保留旧项目和旧客户端
兼容；新 `page_plan` 存在时，预览和导出不再实时读取它重新分段。同步入场、同步退场和
段末清屏仍属于普通显示设置，但使用新页面计划提供的段落 ID。

## 6. 消费端改造清单

### 6.1 `models.py`

- 新增加载设置、页、段、计划与稳定布局 ID；
- `TimingTrack` 携带可选页计划；
- `Style` 保存 1～8 默认布局映射；
- 序列化与校验：未知 ID、重复 ID、越界行数和空页安全回退；
- `style_to_dict/from_dict` 保持旧布局字段兼容。

### 6.2 `engine/page_plan.py`（新增）

- 成为段页构建、解析、投影、规范化和编辑的唯一业务入口；
- 使用不可变快照或深拷贝友好的 dataclass，便于撤销和 multiprocessing spawn；
- 纯函数优先，UI 不参与业务判断。

### 6.3 `engine/timeline.py`

- `assign_lanes()`、`compute_display_lines()`、`visible_display_lines()` 改为消费统一解析结果；
- 保留 `page_plan is None` 的 legacy 分支供旧测试和裸调用；
- section ID 不再仅由 `section_gap_ms` 临时计算；
- 同步入场、同步退场、段末清屏按显式 section；
- Bottom 短页、ForceBottom、lane 冲突、lead/tail 和覆盖时间保持现有语义。

### 6.4 `engine/painter.py`

- `_visible_lines_for_style()`、`display_windows_for_style()`、
  `display_schedule_for_style()` 使用新 lane/section/page；
- `_renderable_page_lines()` 和 SmartHorizon 使用明确同页成员；
- `_style_for_line()` 通过页布局稳定 ID 解析，同时保留逐行兼容投影；
- Top/Middle/Bottom 的短页轨位映射按已确认规则扩到 1～8；
- 页计划、各页布局 ID 和默认布局映射进入 `_track_layout_signature()`；
- margin warning、单行页居中、页宽和 N3 `n3_1074` 页首布局语义保持一致。

### 6.5 预览

`preview_view.py`、`preview_graphics.py` 和异步预览继续接收 `TimingTrack`，不维护自己的
页状态。track 原地变更后必须重新喂给 worker，确保缓存失效。主轨与副轨都使用各自计划。

### 6.6 导出

`RenderJob` 已携带主/副 `TimingTrack`，新 dataclass 必须可 pickle；单进程、多进程
spawn、GPU 打包和 CPU fallback 得到同一计划。导出不读取任何 UI 控件作为分页来源。

### 6.7 Native/GPU 协议

虽然产品 native 入口硬关闭，`native_protocol.track_to_ir()` 仍需从统一解析结果写入
lane、page index、section index、页面布局和显示窗口，保持协议测试与 GPU 回退一致。
不得在协议层再次调用旧分页算法。

### 6.8 底部字幕时间轴

`timeline_view.build_lanes()` 的一条 lane 代表一个字幕源，不等于页面 T1～T8，无需改变
基本轨道数；但它使用的显示窗口必须由新计划计算。页面编辑后刷新 `_windows` 和静态
pixmap，不能丢失当前选中歌词。

### 6.9 歌词列表

- 引入展示行适配层；

## 9. 风险与防线

1. **UI 行号错位**：必须先建立展示行适配层，再添加虚拟行；
2. **预览与导出分叉**：所有消费端只认统一 resolved page 结果；
3. **旧索引漂移**：默认布局只追加，稳定 ID 为新版权威；
4. **刷新误覆盖**：手工结构提示、事务替换、可撤销；
5. **缓存旧帧**：页计划和默认映射进入签名；
6. **副轨漏改**：所有 payload、刷新、预览和导出测试同时覆盖 extra tracks；
7. **N3 回归**：保留页首 LayoutIndex、显式边界、Bottom 短页与 ShowBegin/End；
8. **空页污染**：每次编辑和刷新后统一 normalize；
9. **旧客户端**：保存兼容逐行数组，未知新字段可忽略；
10. **布局缩容级联**：修改前计算影响摘要，修改与重排作为单步撤销。
