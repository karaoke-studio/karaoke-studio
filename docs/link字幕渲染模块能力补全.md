# Lin-K 字幕渲染模块能力补全规划

> 本文档梳理 Lin-K Lyrics（凛K）第 5 步「字幕视频生成」模块在完成 Skia 跨平台渲染底座（Vulkan / Metal / Raster）与 N3 兼容基础后的下一阶段能力补全方向，重点覆盖视觉质感、排版编排、调试效率、音画融合与可扩展特效管线。

---

## 1. 背景与定位

当前 `krok_helper/subtitle_render/` 与 `native/subtitle_renderer/` 已具备完整的日系卡拉 OK 制作能力：`.sug` / `.lrc` / `.n3proj` 输入、竖排与 RTL、上下双注音、多角色与行内逐字配色、行背景带、音量柱/指示灯/导唱符、多种内置入退场与唱字/扫字线粒子、以及 MP4 / ProRes 4444 / QuickTime 动画 / PNG 序列导出。

下一阶段的演进目标是在**不破坏既有 `.yurika` 工程与 N3 导入兼容语义**的前提下，补齐高阶 MV 后期质感、非固定模板化样式表达、音画联动渲染以及可视化调优工具链，充分发挥 Skia GPU 管线的潜力。

---

## 2. P0 · 静态文字外观与基础绘制补全（优先落地）

该阶段改动集中在静态样式模型与 Skia 核心绘制管线，投入产出比最高，无需引入脚本系统即可显著提升成片质感。

### 2.1 阴影与外辉光解耦共存 + 阴影参数增强
- **现状局限**：当前文字装饰字段 `DecorationKind`（`"none" | "shadow" | "glow"`）使阴影与外发光二选一互斥；文字阴影仅支持硬边 XY 偏移，不支持模糊半径与扩散。
- **补全目标**：
  - 将文字阴影与外辉光拆分为独立可叠加的装饰层，支持同一状态同时启用投影与外发光。
  - 为文字阴影补齐：**高斯模糊半径、外扩张（Spread）、方向角 + 偏移距离、渐变阴影与独立不透明度**。
  - 优化外辉光绘制：支持外扩张参数，并通过轮廓抠空（扣除字形与描边本体区域）确保**透明填充或半透明描边文字**也能呈现干净的外发光，且双态一致时整行绘制不被扫字边界切分。

### 2.2 渐变填充体系升级
- **现状局限**：`PaintFill` 目前仅支持纯色、水平/垂直线性渐变、垂直硬切拼色与图片填充，缺少径向渐变、任意角度控制、坐标参考框切换与感知色空间插值。
- **补全目标**：
  - 补齐**任意角度线性渐变**与**径向/椭圆渐变**（中心点 + XY 半径）。
  - 支持三种渐变坐标空间：**画布（Canvas）/ 整行（Line）/ 按单字（Glyph）**。
  - 增加 **Linear RGB / HSV / OKLCH** 色彩插值空间与色相环方向选项，改善大跨度配色渐变的灰暗断层；对斜向硬边拼色增加约 1 设备像素的抗锯齿柔化。

### 2.3 扫字过渡带羽化与高亮混合模式
- **现状局限**：走字前后切换边界为硬切裁剪（现有羽化参数仅作用于叠加的扫字高亮带）；高亮带缺少混合模式选择。
- **补全目标**：
  - 为未唱 → 已唱交界增加可调宽度的**软边过渡带羽化**（默认 0 保持硬切兼容）。
  - 为扫字高亮带增加混合模式选项：**正常（Normal）/ 滤色（Screen）/ 叠加（Add）**，增强亮色背景上的光感融合。

### 2.4 显式多级字体回退链
- **现状局限**：目前以日文槽 + 英数槽二元体系为主，缺字回退依赖预热字体发现，用户无法为单套样式指定多级备选字体顺序。
- **补全目标**：在样式方案中暴露有序的多级回退字体列表，按声明顺序匹配字形，提升中日英韩及特殊符号混排时的确定性与可控性。

## 3. P1 · 排版编排、样式继承与创作调试能力

### 3.1 开关式多层样式继承与属性溯源
- **现状局限**：应用级样式预设库在导入工程角色时为一次性深拷贝，与工程样式无持续联动；单行/局部特写缺乏细粒度属性级透传继承。
- **补全目标**：
  - 建立 **工程默认 → 字幕轨 → 布局/分区 → 单行 → 逐字角色** 的开关式覆盖模型：开启即写入覆盖，关闭则自动透传上级值。
  - 修改全局或轨道样式时自动同步全曲，同时安全保留局部覆写；在属性面板标示每个当前生效属性的继承来源。

### 3.2 连字与字簇保护的真实墨迹注音避让
- **现状局限**：现有注音间距避让围绕离散单元与描边宽度求解，在复杂连字、组合字符或极端长注音场景下存在局限。
- **补全目标**：依托 Skia 管线已有的 FreeType / HarfBuzz 真实字形墨迹与 cluster 边界信息，先识别跨字符的刚性连字/字簇组，再以**整组刚性平移**的方式消除相邻长注音的挤叠碰撞，不拉伸字形、不拆散连字，并给出无法分离时的明确诊断提示。

### 3.3 灵活场景编排与退场副本机制
- **现状局限**：布局体系围绕 1–8 行固定 lane 网格展开；单行离场在槽位复用或时间压缩时容易被截断。
- **补全目标**：
  - 在兼容现有 N3 行网格的基础上，逐步引入可组合的区域/槽位容器与按段落（副歌/合唱/过场）路由到不同布局区域的编排能力，切换区域时保持前后句轮换节奏上下文。
  - 引入**行退场副本（脱离原槽位继续独立演化）**能力，使碎散、翻折、消融类退场动画在下一句接替槽位后仍可自然播完。
  - 前奏倒计时/导唱符扩展支持直接内嵌自定义 SVG 矢量图形，并提供首字上方自动避让注音的附着模式。

### 3.4 单帧分阶段性能剖析与画布检查叠加层
- **现状局限**：渲染性能与排版边界排查目前依赖日志和离线脚本，创作者与开发者在界面内缺少直观诊断视图。
- **补全目标**：
  - 在引擎层采集并向前端暴露**单帧分阶段耗时剖析**（布局准备、特效求值、滤镜/材质、粒子、栅格化、读回/提交及内存开销）。
  - 在预览画布提供可开关的**可视化检查叠加层**：叠加显示字形真实墨迹框、HarfBuzz 字簇边界、注音归属范围、走字锋面位置与粒子发射区域。

### 3.5 导出预检、抽样验证与开放字幕格式扩展
- **导出保障**：导出前增加工程完整性检查与开头片段（普通 / 透明双通道）快速抽样验证，导出完成输出包含降级提示与统计数据的结构化报告。
- **字幕格式扩展**：在 `.sug` / Nicokara `.lrc` / `.n3proj` 之外，视需求逐步补齐主流逐字字幕格式（含 `\k`/`\kf`/`\ko` 的 ASS/SSA、TTML/AMLL、Enhanced LRC）的导入，以及带字段差异/损失提示的导出能力。
- **时间精度演进**：评估核心渲染管线由毫秒整数向微秒精度平滑演进，消除 29.97 / 60 / 120fps 下的亚毫秒取整累积漂移。

## 4. P2 · 音画融合驱动与可扩展 GPU 特效管线

该阶段将 Lin-K 字幕渲染从“固定参数动画器”升级为“可感知音画、可扩展材质与特效的 MV 渲染引擎”。

### 4.1 离线确定性音频特征驱动
- 对项目音轨执行离线确定性分析（固定重采样与 hop 步长），提取**低频能量包络、瞬态鼓点脉冲、节拍相位与置信度**时间序列并缓存。
- 将音频特征注入渲染管线：优先支持驱动现有内置特效（整字缩放、发光强度脉冲、粒子发射速率、扫字线能量与背景带动态），后续开放给自定义特效消费。

### 4.2 背景画面视觉特征感知
- 对背景视频/图像执行离线确定性区域特征统计（含可配置时域平滑窗口），提取任意矩形区域的**线性预乘色彩均值、亮度均值与方差、多分区光色及局部光流场**。
- 赋能 MV 画面级融合效果：文字阴影方向与冷暖色温随画面主光源自适应、金属/玻璃材质自动采样背景环境色、粒子与焦外散景自动吸取画面配色。

### 4.3 基于 SkSL 的声明式滤镜图与可扩展特效包
- 充分利用现有 C++ Skia（`SkRuntimeEffect`）能力，构建**声明式图像滤镜图**（组合 `RuntimeShader` / `Blur` / `Mask` / `Transform` / `Blend` 节点）与可扩展材质/特效包机制：
  - 支持纯配置 + SkSL 编写高阶材质与后期效果：**液态/磨砂玻璃折射、金属镀铬、棱镜色散辉光、半调网点、扫字前沿火焰/侵蚀、水面波纹倒影、CRT 扫描故障**等。
  - 补充逐字/字簇级自由变换与**网格变形（Grid Warp）**原语，支持水面微震、风蚀扭曲等非刚性文字动画。
  - **透明导出安全回退**：任何依赖背景像素采样的材质/滤镜须显式声明透明背景下的兜底外观或旁路策略，保证导出 ProRes 4444 / QuickTime 动画 / 透明 PNG 序列时画面干净无黑块。
  - **确定性约束**：所有扩展逻辑均须保持纯函数求值与确定性随机，严禁依赖实时帧率或可变全局状态，确保预览任意跳转与最终导出严格逐帧一致。

## 5. 实施约束与兼容原则

1. **旧工程零回归**：所有新增样式与布局字段必须具备向后兼容的默认值，已保存的 `.yurika` 工程与 `.n3proj` 导入结果在未启用新能力时保持既有渲染语义不变。
2. **以 Skia 主管线为演进载体**：P0–P2 的新视觉能力（如模糊/外扩阴影、OKLCH/径向渐变、羽化扫字、SkSL 材质与音画驱动）统一在 Skia 跨平台核心落地，不再向已冻结的旧后端重复实现。
3. **预览与导出严格同口径**：新增的每一项样式、滤镜、音画特征采样与透明降级策略均须由预览与导出共享同一执行内核，避免“预览与成片不一致”。
