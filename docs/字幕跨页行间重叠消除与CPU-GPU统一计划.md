## 2. 当前问题

### 2.1 冲突判断使用了逻辑行位，而不是实际绘制范围

当前跨页冲突处理主要以同一 `lane`/行位作为判断依据。该判断只在前后页面使用相同布局、相同行位具有相同像素位置时近似成立。

在每页可以独立选择 1～8 行布局以后，以下情况都可能打破该假设：

- 两个页面使用不同的行数布局；
- 两个布局的上下余白、行间距或对齐方式不同；
- 前页的第二行和后页的第一行在画面上实际重叠；
- 行位编号相同，但两个布局中的实际像素位置不同；
- Ruby、描边、阴影或发光超出了正文的字体框。

因此，是否重叠必须以最终绘制内容的像素上下界或左右界判断，不能继续以行位编号判断。

### 2.2 时间压缩需要保留走字区间与入场动画下限

现有 `show_time.py` 中的同位置调整会压缩前后页的提前入场和延迟退场区间。该能力需要保留，用于先减少不必要的过渡重叠，但必须遵守明确下限：

1. 它仍无法识别不同布局、不同逻辑行位之间的实际空间重叠；
2. 自动压缩不得使上屏时间晚于“本行走字开始 − 有效入场动画时间”；
3. 自动压缩不会把非零入场动画缩短到 250ms 以下；若用户明确把动画时长设为
   小于 250ms，或手工修改上屏时间，则保留用户值；
4. 自动压缩不得使消失时间早于本行走字结束，退场动画允许缩短至 0ms；
5. 时间压缩后仍存在的冲突交给空间避让。

歌词走字时间和用户手工覆盖仍保持不变；自动生成的 PreTime/PostTime 以及其中的
入场、退场动画区间可以按上述下限缩短。

### 2.3 CPU 与 GPU 的重叠行为不一致

当前实现中：

- CPU QPainter 会按顺序绘制所有处于显示窗口内的行，后绘制的内容覆盖先绘制内容；
- GPU Direct2D 会按 `(sourceIndex, lane)` 只保留一条可见行，可能直接抑制另一页的行；
- CPU 与 GPU 对显示结束点均存在闭区间判断，精确落在边界毫秒时可能同时显示前后两行；
- CPU 的基线解析仍存在由全局行位映射覆盖分页布局几何的路径，无法作为 1～8 行混排的稳定依据。

本次改造必须同时统一 CPU 和 GPU。不能只在其中一个后端增加补丁。

## 3. 目标与非目标

### 3.1 目标

1. 以最终绘制像素包围范围判断跨页字幕是否重叠。
2. 保留受走字区间和入场动画下限保护的时间压缩，再通过平移后进入页面消除剩余遮挡。
3. 页面作为刚性整体移动，保留页面内部各行的相对位置。
4. CPU 预览、CPU 导出、GPU 预览和 GPU 导出消费同一份解析结果。
5. 修复 CPU/GPU 在无法完全避让时的绘制内容和层叠顺序差异。
6. 保证正文、Ruby、描边、阴影、发光、引导符号和动画使用同一个页面位移。
7. 兼容旧 `.yurika` 项目，并使旧项目默认进入新的正常、不重叠模式。
8. 保留用户显式启用旧行为的入口，便于特殊效果和问题对照。

### 3.2 非目标

1. 不修改 SUG submodule 的工程结构或渲染逻辑。
2. 不修改歌词的走字时间和手工显示时间。
3. 不通过缩放、隐藏字幕或自动换用其他布局解决冲突。
4. 不禁止用户设置可能产生冲突的布局、时间或负行间距。
5. 不处理同一页面内部由用户布局造成的重叠。
6. 本阶段不自动避让标题、背景素材或不同字幕源之间的内容。

## 4. 已确认的产品规则

### 4.1 全局开关

在布局页的“垂直与方向”区域增加复选框：

> 启用行间重叠

该开关是项目级全局字幕样式设置：

- 不属于单个 `LyricsLayout`；
- 不随当前选择的分页布局切换；
- 不写入或覆盖 1～8 行布局预设；
- 在项目 `.yurika` 中持久化；
- 新项目默认关闭；
- 旧项目缺少字段时迁移为关闭。

“垂直与方向”区域目前同时包含布局级 `line_gap_px` 和项目级 `vertical`、`right_to_left`。新开关应与后两者一样通过全局 Style 更新路径保存，不能接入 `_update_layout_field`。

建议字段名：

```python
allow_inter_page_line_overlap: bool = False
```

如果“保存应用默认样式”保存的是完整 Style 快照，该字段可以随完整样式保存；但它不得进入 `LYRICS_LAYOUT_FIELDS`，也不得被“保存为某行数默认布局”修改。

### 4.2 开关语义

| 状态 | 行为 |
|---|---|
| 关闭（默认） | 先执行受走字区间和入场动画下限保护的时间压缩，再使用像素范围检测和空间避让 |
| 开启 | 保留同一套时间压缩，但不执行空间避让，允许不同页面的字幕在画面中发生重叠 |

即使开启旧行为，CPU 和 GPU 也必须绘制相同的可见行，并使用相同的层叠顺序。该开关只切换跨页避让策略，不应重新引入后端差异。

建议悬停说明：

> 系统会自动缩短发生冲突的提前入场和延迟退场时间，但不会截断任何走字区间。自动压缩可以缩短动画时段：不会把非零入场动画自动压到 250ms 以下；若动画时长或上屏时间由用户手工设定，则保留用户值；退场动画可以缩短为 0ms。关闭时，还会根据字幕正文、注音、描边、阴影和发光在布局完成后的绘制范围，移动后进入的整页字幕；页面一旦移动，会保持位置直到本页播放完毕。入场、退场和字符动画允许互相穿越。开启后不执行空间避让，允许跨页字幕重叠，适合需要刻意叠放的特殊效果。同一页内部的负行间距或手工重叠不受此开关影响。

### 4.3 手工时间优先

手工显示时间和用户制造的时间冲突始终有效：

- 不拒绝保存；
- 不自动截短；
- 不自动延后；
- 不覆盖用户的时间设置；
- 空间允许时移动页面避让；
- 空间不足时先搜索反方向；双向都没有完整空间时保留原始位置和既有绘制优先级。

### 4.4 整页刚性移动

后进入页面中的全部字幕行使用同一个位移量：

- 页面内部行间距不变；
- 页面内部各行相对位置不变；
- 正文与 Ruby 的相对位置不变；
- 页面的描边、阴影、发光、信号和动画整体同步；
- 位移不写回布局配置，也不改变项目中保存的布局坐标。

这样既保持布局设计，又能让用户直观看出是整页布局与前页发生了冲突。

### 4.5 跨页间距

避让时使用被重叠页面当前布局的 `line_gap_px` 作为两个页面之间的目标空隙。
新页同时碰到多个旧页时，每一组碰撞分别使用对应旧页布局的行间距。

此间距只用于跨页空间求解，不改变页面内部的原始排版。

### 4.6 画面空间不足

若画面内不存在完全无重叠的位置：

1. 不修改时间；
2. 不缩放；
3. 不隐藏任何一页；
4. 先在布局锚定方向寻找能完整容纳静态碰撞箱的位置；
5. 首选方向越界或无解时，在反方向寻找完整空间；
6. 双向都无解时不产生越界位移，回退到未经避让的原始位置；
7. 回退时保持旧页先绘制、新页后绘制的既有优先级；
8. CPU 和 GPU 必须得到相同结果。

## 5. 统一数据与渲染模型

### 5.1 时间区间

所有后端统一使用半开区间：

```text
[display_start_ms, display_end_ms)
```

即：

```text
display_start_ms <= current_ms < display_end_ms
```

这样可以消除前一行结束时间等于后一行开始时间时的边界双显。

开启旧行为时，仍可以沿用现有同位置时间调整结果；但最终的可见性判断也必须使用半开区间。

### 5.2 空间区间

不需要对整张 RGBA 图进行逐像素相交检测。每一行只需得到最终画布坐标中的一维包围区间：

- 横排：该行所有绘制像素的 `min_y` 和 `max_y`；
- 竖排：该行所有绘制像素的 `min_x` 和 `max_x`。

区间必须覆盖该行的全部可见组成：

- 正文；
- Ruby；
- 一重、二重描边；
- 阴影；
- 发光；
- 引导符号；
- 字符级样式覆盖；
- 视图缩放、旋转、平移；
- 布局完成后的静态文字位置。

入场、退场、逐字符变形和行信号等动画轨迹不扩大碰撞箱；它们仍随页面位移一起绘制，并允许在动画过程中互相穿越。

这是保守的一维带状检测。以横排为例，即使两行在 X 方向没有相交，只要最终 Y 区间相交，也视为发生行间冲突。该规则符合“只按一行内全部像素的最大、最小 X 或 Y 判断”的已确认优化。

### 5.3 时间与空间同时相交

仅当以下两个条件同时成立时，才需要避让：

1. 两行显示时间区间相交；
2. 两行在分离轴上的像素区间相交或小于目标跨页间距。

同页内的行不进入此求解器；求解器只比较不同页面。

### 5.4 建议的中间结构

具体命名可在实现中调整，但共享解析结果至少应表达：

```python
@dataclass(frozen=True)
class LineVisualBand:
    source_index: int
    track_line_index: int
    segment_index: int
    page_index: int
    line_index_in_page: int
    display_start_ms: int
    display_end_ms: int
    axis_min: float
    axis_max: float


@dataclass(frozen=True)
class ResolvedPagePlacement:
    source_index: int
    segment_index: int
    page_index: int
    offset_x: float
    offset_y: float
    line_bands: tuple[LineVisualBand, ...]
```

这里的页号必须来自已经解析完成的显式段页计划，不能再从 `lane` 推断页面。

## 6. 空间避让算法

### 6.1 输入

求解器接收：

- 已解析的段、页和页内行关系；
- 每页实际使用的布局；
- 每行最终生效的角色、字体和特效；
- 基础显示窗口及手工时间覆盖；
- 目标画布尺寸、DPR 和视图变换；
- 每行在未避让状态下，由正文、Ruby、描边、阴影和发光组成的静态墨水像素区间；
- 页面锚定方向；
- 每个已占用页面所属布局的 `line_gap_px`。

单行静态墨水区间不得包含字体度量中的透明留白、布局行间距或任何动画轨迹。
`line_gap_px` 只在候选位移公式中作为碰撞箱之间的目标空隙加入一次。

### 6.2 处理顺序

每个字幕源独立按页顺序处理：

1. 计算当前页未经避让时的基础位置和所有行的像素区间；
2. 找出所有显示时间仍与当前页相交的先前页面，不限于紧邻的前一页；
3. 对当前页的每一行，与这些先前页面的每一行进行“时间区间 + 空间区间”检测；
4. 生成使边界刚好分离的候选整页位移；
5. 过滤掉任何会使完整静态碰撞箱超出画布的候选；
6. 优先在页面锚定方向选择满足跨页间距的候选，首选方向无解时搜索反方向；
7. 双向都无法满足跨页间距时，按相同方向顺序寻找仅保证实际像素不重叠的候选；
8. 双向都没有完整无重叠空间时返回零位移，使用原始位置和既有绘制优先级；
9. 将同一位移应用到当前页全部行；最终绝对位置由碰撞边界决定，不再二次套用上/下余白；
10. 把已经移动后的区间加入占用集合，继续处理后续页面。

该流程必须覆盖三页及更多页面同时显示的情况。

### 6.3 候选位移

以横排字幕为例，先前占用带为：

```text
[previous_min_y, previous_max_y]
```

后进入页面整体范围为：

```text
[incoming_min_y, incoming_max_y]
```

后页向上移动、与前页保持目标间距的候选位移为：

```text
delta_y = previous_min_y - previous_gap - incoming_max_y
```

后页向下移动的候选位移为：

```text
delta_y = previous_max_y + previous_gap - incoming_min_y
```

竖排时使用对应的 X 区间和 `delta_x`。

多组冲突不能通过对单个冲突反复做易抖动的局部修补解决。应收集各个接触边界形成的候选位移，统一验证候选是否满足全部仍有效的占用带。

### 6.4 方向偏好

- 下对齐页面：优先向上移动，画布内无解时搜索向下；
- 上对齐页面：优先向下移动，画布内无解时搜索向上；
- 居中页面：选择绝对位移较小的可行方向；
- 竖排页面：在 X 轴上使用与布局列方向一致的对应规则；
- 相同代价必须使用固定的确定性顺序，不能随帧或容器遍历顺序改变。

### 6.5 画面空间不足时的代价

候选始终必须完整位于画布内，并按以下顺序选择：

1. 满足各被重叠页面布局的 `line_gap_px`；
2. 首选锚定方向；
3. 反方向；
4. 无法满足间距时退化为静态碰撞箱不相交，并重复方向顺序；
5. 双向都无解时回退原位；
6. 同组候选选择离原布局位置最近者，并以固定页序稳定决胜。

### 6.6 稳定性

每页只计算一个稳定偏移。页面一旦因碰撞发生位移，即使导致碰撞的前页随后消失，也必须保持该位置直到本页完整结束显示，避免观众视线被中途回位打断。

建议做法：

- 正文、Ruby、描边、阴影和发光按真实字形路径计算完整静态墨水包围区间；
- 字体度量矩形和 `line_gap_px` 不进入单行碰撞箱；
- 入场、退场和逐字符动画之间允许重叠，所有动画轨迹均不进入碰撞箱；
- 以每页全部行的显示窗口判断它与先前页面是否曾经同时显示；
- 对页面整个显示生命周期一次性求解固定偏移；
- 已移动页面的碰撞箱继续加入后续页面的占用集合；
- Native IR 仍使用位移窗口传输，但同一页只有覆盖完整页生命周期的一个固定窗口。

不应在每一帧读取完整 RGBA 后扫描非透明像素。

## 7. 旧行为与新行为的时间路径

关闭“启用行间重叠”时：

1. 保留基础 `PreTime`、`PostTime`、`IntervalTime` 和手工覆盖的语义；
2. 使用 `_adjust_same_position` 压缩同位置的自动过渡时间；
3. 自动上屏不得晚于“走字开始 − 有效入场动画时间”；自动压缩不得把非零入场
   缩短到 250ms 以下，用户明确设置的更短动画或手工上屏时间除外；自动消失
   不得早于走字结束，退场动画允许缩短至 0ms；
4. 通过固定页面空间位移处理压缩后剩余的跨页冲突；
5. 手工覆盖后的时间原样进入求解器。

开启“启用行间重叠”时：

1. 保留现有按逻辑行位处理的过渡时间算法；
2. 不执行新的跨页空间避让；
3. 如果旧算法留下实际像素重叠，按统一的旧页到新页顺序绘制全部可见行；
4. GPU 不再按 `(sourceIndex, lane)` 删除其中一条。

`ForceBottom` 等现有显示时间和页行位语义需要在两种模式下继续生效，但不得越过显式段页计划重新推断分页。

## 8. CPU QPainter 改造

### 8.1 先修正每页布局几何

像素碰撞检测依赖正确的基础几何，因此应先修复 CPU 的布局消费路径：

- 每行基线从该行所属页面的实际布局计算；
- 支持 1～8 行页面混排；
- 不再用只以 `lane` 为键的映射保存跨页布局结果；
- 不能让后处理页面覆盖先处理页面的同编号行位；
- 短页偏移继续服从显式页计划和当前布局；
- 布局、角色、字符样式的覆盖顺序保持现状。

建议内部键至少包含：

```text
(source_index, track_line_index)
```

或者：

```text
(source_index, segment_index, page_index, line_index_in_page)
```

不能只使用 `lane`。

### 8.2 复用权威文字几何

优先复用 QPainter 当前的文字运行组合器、Ruby 层和装饰层几何，扩展为逐行的最终包围区间。不要另写一套近似字号公式，否则正文、Ruby 与碰撞范围会再次分叉。

现有 `_subtitle_lines_vertical_bounds`、`_display_line_vertical_bounds` 和 `_line_layer_stack` 可作为改造入口，但需要：

- 从“当前帧所有行的汇总范围”下沉为可缓存的逐行范围；
- 支持分页键和整页位移；
- 覆盖竖排及最终视图变换；
- 输出空间求解器可消费的统一结构。

### 8.3 应用位移

页面位移必须在该行的全部层共用的父级坐标上应用，避免出现：

- 正文移动、Ruby 未移动；
- 字形移动、发光或阴影仍留在原位置；
- 点击/范围警告使用原位置；
- 导出裁剪范围没有包含移动后的字幕。

## 9. GPU Direct2D 与协议改造

### 9.1 Python 为语义权威

页面布局、显示时间、像素区间和最终页面位移由共享的 Python 解析层计算。GPU 只消费结果并绘制，不在 C++ 中重新实现一套避让决策。

CPU QPainter 继续作为 oracle 和永久 fallback。

### 9.2 Native IR

Native IR 中每条可绘制行需要携带最终解析结果，例如：

```json
{
  "display_start_ms": 1000,
  "display_end_ms": 2500,
  "page_index": 1,
  "layout_offset_x": 0.0,
  "layout_offset_y": -96.0
}
```

具体字段名可以调整，但必须满足：

- 位移基于目标渲染宽高、DPR 和最终布局计算；
- `build_render_ir` 向轨道解析路径提供所需画布信息；
- CPU 与 GPU 使用同一个解析器或同一可序列化结果；
- 字段在主字幕和附加字幕源中一致；
- 无位移时明确为 `0`，不能依赖 native 端猜测。

### 9.3 Direct2D 绘制

Direct2D 需要：

- 删除按 `(sourceIndex, lane)` 只保留第一条活动行的去重；
- 使用半开时间区间；
- 绘制所有共享解析器判定为可见的行；
- 将页面位移应用于正文、Ruby、特效、信号和用于合成的范围；
- 无法避让时按旧页先、新页后的统一顺序绘制；
- 保持 G5 shared-memory/QImage 预览和 GPU 导出路径一致；
- 不重新启用已停止的 G6 DirectComposition 产品路径。

## 10. 数据兼容与迁移

### 10.1 `.yurika`

旧项目没有 `allow_inter_page_line_overlap` 字段时：

```text
迁移结果 = False
```

这是一项有意的视觉行为修正。旧项目打开后默认使用新的不重叠算法，而不是为保持旧画面自动开启旧行为。

保存项目后写入明确字段。若 Style 当前采用字段驱动序列化，优先沿用该机制，不为本字段单独提高工程结构版本；仍需通过测试确认：

- 缺字段读取为 `False`；
- `False` 和 `True` 均可往返保存；
- 旧客户端遇到新字段时的宽容读取行为不被破坏。

### 10.2 SUG、LRC 和 N3

- SUG、LRC 和 N3 导入时都使用默认关闭；
- 不向源字幕文件回写该设置；
- 不修改 SUG submodule；
- 导入后生成的 `.yurika` 按新字段正常持久化；
- 显式段页计划仍是页面关系的权威来源。

### 10.3 布局预设

该字段不是行数布局字段：

- 不进入 1～8 行默认布局；
- 不随“应用到全部页”批量更换布局；
- 不随页面拖动时的布局容量自适应规则变化；
- 不影响旧项目段页数据解析；
- 不影响页面变为 0 行时的自动删除逻辑。

## 11. 必须同步检查的消费端

| 消费端 | 必须使用的统一结果 |
|---|---|
| CPU 实时预览 | 半开显示窗口、逐页布局、最终页面位移 |
| CPU MP4 导出 | 与 CPU 预览完全相同 |
| CPU 多进程导出 | 缓存键和序列化结果包含页面位移依赖 |
| G5 GPU 预览 | Native IR 中覆盖页面完整生命周期的固定页面位移窗口 |
| GPU 导出 | 与 G5 预览相同 |
| Native Direct2D | 不再按 lane 去重，统一层叠顺序 |
| 正文渲染 | 使用页面最终位移 |
| Ruby 渲染 | 与正文共用同一页面位移 |
| 描边/阴影/发光 | 参与范围计算并同步位移 |
| 引导符号/行信号 | 参与范围计算并同步位移 |
| 动画 | 不扩大碰撞箱，但与正文同步使用当前页面位移 |
| packed bands/内容范围 | 使用位移后的最终范围 |
| `frame_has_content` | 使用半开时间窗口 |
| 画面越界和余白提示 | 检查位移后的最终位置 |
| 时间轴 UI | 时间保持不变，不显示伪造的避让时间 |
| 附加字幕源 | 每个字幕源内部独立求解 |

标题不属于分页行，不参与本次页间避让。不同字幕源之间仍按既有合成顺序叠加；若以后需要跨字幕源避让，应作为独立需求处理。

## 12. 缓存与失效

页面位移不写入项目文件，应作为可重算的派生数据缓存。缓存签名至少包括：

- 字幕源和轨道内容；
- 显式段页计划；
- 每页布局 ID 和布局字段；
- 全局 Style；
- 角色及角色覆盖；
- 字符级样式覆盖；
- Ruby 内容和样式；
- 描边、阴影、发光；
- 引导符号和行信号；
- 行级、字符级动画；
- 显示时间和手工覆盖；
- 目标宽高、DPR 和帧率；
- 视图缩放、旋转和平移；
- 横排/竖排、从右到左；
- `allow_inter_page_line_overlap`。

下列操作必须使相关缓存失效：

- 拖动行或删除分页/分段；
- 修改页面布局；
- 修改字体、字号、Ruby 或特效；
- 修改角色；
- 修改显示时间；
- 修改分辨率或预览尺寸；
- 切换横排/竖排或视图变换；
- 切换“启用行间重叠”。

## 14. 测试矩阵

### 14.1 模型与 UI

- 新 Style 默认为关闭；
- 旧项目缺字段读取为关闭；
- 开启和关闭均可往返保存；
- 切换页面布局不改变开关；
- 切换布局预设不改变开关；
- 保存某行数默认布局不携带开关；
- 悬停说明完整；
- SUG/LRC/N3 导入均默认关闭。

### 14.2 时间

- 精确结束毫秒使用半开区间，不双显；
- 两种模式都保留同位置自动时间压缩；
- 压缩后的自动上屏时间不得晚于“走字开始 − 有效入场动画时间”；
- 自动压缩不得把非零入场动画缩短到 250ms 以下；用户明确设置的更短动画或
  手工上屏时间除外；
- 压缩后的消失时间不得早于走字结束，退场动画可以缩短至 0ms；
- 手工开始、结束时间保持原值；
- 三页及以上同时显示时全部进入空间求解。

### 14.3 基础布局

- 2 行页接 1 行页，前页 T2 与后页 T1 重叠；
- 1、2、3、4、8 行布局任意相邻组合；
- 页面实际行数小于布局容量；
- 上对齐、下对齐和居中；
- 横排和竖排；
- 从右到左；
- 不同上下余白和不同 `line_gap_px`；
- 后页使用较大手工布局时仍以实际布局计算。

### 14.4 避让

- 使用被重叠页 `line_gap_px`；同时碰撞多个旧页时分别取各自布局值；
- 后页整页刚性移动；
- 同页内部负行间距保持不变；
- 多个前页占用时不只检查相邻页；
- 可避让时没有跨页区间相交；
- 首选方向越界时能改向反方向避让；
- 双向空间不足时回退原位且新页仍在旧页上层；
- 避让产生的非零位移不得使完整静态碰撞箱超出画布；
- 页面偏移覆盖本页完整显示生命周期，不中途回位。

### 14.5 像素范围

- 正文；
- Ruby；
- 一重和二重描边；
- 阴影；
- 三档发光；
- 字符级字体和字号；
- 引导符号和行信号；
- 行动画和字符动画不进入静态碰撞箱；
- 缩放、旋转和平移；
- 正文和 Ruby 在移动后仍保持原相对位置。

### 14.6 CPU/GPU 一致性

- CPU 不再因 lane 键覆盖不同页面；
- GPU 不再删除相同 lane 的另一页；
- CPU/GPU 可见行集合一致；
- CPU/GPU 页面位移一致；
- CPU/GPU 最终像素区间一致；
- CPU/GPU 画布边界回退和层叠顺序一致；
- CPU 预览与 CPU 导出一致；
- GPU 预览与 GPU 导出一致；
- packed bands 包含位移后的全部像素。

## 15. 验收标准

### 15.1 功能验收

在“启用行间重叠”关闭时：

- 不同分页布局之间以实际像素范围检测冲突；
- 画面内有足够空间时，跨页字幕的静态碰撞箱不得遮挡；
- 避让不得把完整静态碰撞箱移出画布；双向无解时回退原位；
- 字幕显示时间不得因避让发生变化；
- 后页整页移动，内部布局保持不变；
- Ruby 与正文不发生错位；
- CPU 和 GPU 结果一致。

在“启用行间重叠”开启时：

- 保留旧时间处理和允许重叠的效果；
- CPU 和 GPU 仍显示相同内容；
- 冲突时使用旧页先、新页后的相同层叠顺序。

### 15.2 兼容验收

- 旧 `.yurika` 无需用户操作即可进入新的不重叠模式；
- 保存旧项目不会丢失段、页、布局、角色、Ruby 或时间覆盖；
- SUG/LRC/N3 导入不受破坏；
- 现有 1～8 行默认布局和旧标题预设不受影响；
- 不修改 SUG submodule。

### 15.3 性能验收

- 不做逐帧完整 RGBA 像素扫描；
- 页面范围和位移可以稳定缓存；
- 普通 1080p/60fps 预览无可感知退化；
- 4K、8 行、Ruby、发光和动画组合下不出现持续性主线程卡顿；
- GPU fallback 仍能无缝回到 CPU。
